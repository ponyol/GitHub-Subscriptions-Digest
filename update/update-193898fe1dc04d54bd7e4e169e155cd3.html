Функции Tensorlake теперь имитируют обычные функции Python, копируя метаданные, что значительно улучшает их совместимость с агентскими фреймворками, такими как OpenAI, и позволяет корректно генерировать описания инструментов. Пример `city_guide` был значительно переработан, чтобы продемонстрировать контейнеризованные инструменты с подробными докстрингами и включить вспомогательную функцию для безопасного удаленного выполнения кода для таких задач, как конвертация температуры.

- Add message update to documentai sdk (#458) - Tensorlake Function mimic regular functions and extend city guide readme example (#460) Make Tensorlake Functions mimic regular functions as much as possible This results in correctly generated tool descriptions by OpenAI agentic framework, i.e. after updating the city guide example in this PR the weather tool description in the created agent is exactly the same as when no @function() decorator is used: ``` Agent(name='Guide Creator', handoff_description=None, tools=[FunctionTool(name='weather_tool', description='', params_json_schema={'properties': {'city': {'title': 'City', 'type': 'string'}}, 'required': ['city'], 'title': 'weather_tool_args', 'type': 'object', 'additionalProperties': False}, on_invoke_tool=<function function_tool.<locals>._create_function_tool.<locals>._on_invoke_tool at 0x10ca5d5a0>, strict_json_schema=True, is_enabled=True, tool_input_guardrails=None, tool_output_guardrails=None), ``` Now OpenAI `@function_tool` decorator can be applied to a Tensorlake Function. The OpenAI decorator has to be at the top of the decorator chain because it returns a non-callable dataclass. This approach would work for other agentic frameworks without any extra custom wrappers/decorators needed per agentic framework. I did an implementation that requires minimal changes where our Function object mimics as much as possible to a regular python function. If we find that this mimicking is not sufficient for some other agentic frameworks then we can do a full more intrusive implementation where we generate regular python functions. This would 100% work in all cases with all frameworks but requires more work and maintenance complexity so I'm doing doing this now because the already implemented approach might work for all the frameworks too. Extending city guide example: Add remote code execution in a function container to convert temperature. Trigger temperature conversion by running the agent for Milan, Italy. Format long strings nicer. Add docstrings to all tools so Agent can potentially use them better. This also shows a more canonical agent code to users. Also verified that it works in remote mode on Tensorlake Cloud.
