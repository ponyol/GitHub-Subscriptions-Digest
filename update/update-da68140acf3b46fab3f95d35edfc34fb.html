- perf(chat): defer fontification during streaming `eca-chat--render-content' called `font-lock-ensure' on the whole chat buffer after every streamed assistant chunk. With fast models that emit many tiny chunks (e.g. gpt-5.3-codex at ~30 chunks/sec, or MiniMax variants) this caused hundreds of full-buffer refontifications per response and substantial CPU / GC pressure during streaming, which on some setups (e.g. with `valign`) could make Emacs visibly unresponsive. Instead, schedule intermediate fontification via a debounced idle timer in a new `eca-chat--schedule-fontify' helper and run a single guaranteed `font-lock-ensure' at end-of-stream, before table alignment so the table beautifier still sees fully-fontified text. Visible-area fontification continues to work lazily via jit-lock's after-change hook. The debounce interval is configurable via the new `eca-chat-fontify-debounce-interval' custom (default 0.15s; `nil' disables intermediate fontify entirely and relies on jit-lock plus the final ensure). Benchmarked on a 20x10 markdown table prompt, same prompt run back-to-back: gpt-5.3-codex (~1020 chunks of ~3 chars, 32 chunks/sec): font-lock-ensure calls 1022 -> 52 (-95%) font-lock-ensure CPU 2.260s -> 0.007s (-99.7%) render-content CPU 2.563s -> 0.269s (-89.5%) Total Emacs CPU 15.8s -> 4.3s (-73%) opus-4.7 (~50 chunks of ~56 chars): font-lock-ensure calls 51 -> 51 (unchanged) font-lock-ensure CPU 0.081s -> 0.013s (-84%) per-call cost 1.59ms -> 0.25ms (-84%) Total Emacs CPU 6.52s -> 2.73s (-58%) Two compounding wins: fast streamers get a ~95% call-count drop (the idle timer rarely fires during bursts, so effectively one final ensure per response); slow streamers keep the same call count but each call is ~6x cheaper because fontify now runs from an idle timer, giving jit-lock time to do incremental work between chunks so most calls just verify already-fontified text. 🤖 Generated with [eca](https://eca.dev) Co-Authored-By: eca-agent <git@eca.dev> - Simplify mode-line trust indicator to emoji-only After shipping 6bf962d with optional nerd-icons / all-the-icons integration, the extra complexity (soft-detect branches, helper defun, toggle defcustom) offered marginal benefit over a simple emoji pair that works for every user without any package install or font setup.
