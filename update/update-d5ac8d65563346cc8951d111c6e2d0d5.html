Суммаризация (на русском)

This release delivers crucial bug fixes and stability improvements, notably resolving a regression that prevented custom HTTP routes from being forwarded from mounted servers, which caused 404 errors. It enhances performance through component list caching in `ProxyProvider` and strengthens security by addressing insecure JWT verification methods and improving OIDC scope handling. The update also includes numerous type-safety refinements, general robustness enhancements, and introduces `FastMCPApp` for composable applications. --- Этот релиз содержит критические исправления ошибок и улучшения стабильности, в частности, устраняет регрессию, из-за которой пользовательские HTTP-маршруты не перенаправлялись с монтированных серверов, что приводило к ошибкам 404. Он повышает производительность за счет кэширования списков компонентов в `ProxyProvider` и усиливает безопасность, устраняя небезопасные методы проверки JWT и улучшая обработку OIDC-областей. Обновление также включает многочисленные улучшения безопасности типов, общие повышения надежности и представляет `FastMCPApp` для создания композитных приложений.

- fix: forward custom_route endpoints from mounted servers (#3462) * fix: forward custom_route endpoints from mounted servers When a child server with custom HTTP routes (registered via @server.custom_route()) is mounted onto a parent, the routes were silently dropped because _get_additional_http_routes() only returned self._additional_http_routes without recursing into mounted providers. This caused 404s for endpoints like /readyz health checks that worked in v2 but broke in v3 (regression). The fix updates _get_additional_http_routes() to traverse providers, unwrap _WrappedProvider layers (from namespace transforms), find FastMCPProvider instances, and recursively collect their server's custom routes.
