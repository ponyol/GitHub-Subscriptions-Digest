Суммаризация (на русском)

This update introduces significant improvements for self-hosted deployments, primarily enabling full support for S3-compatible storage backends with proxy mode, including bundled MinIO/RustFS overlays, and standardizing S3 configuration variables. It also enhances performance and reliability by making the PostgREST proxy connection pool configurable, tightening retry policies, and optimizing real-time dashboard updates through coalescing invalidations. Additionally, the release addresses critical issues such as a stale AI credential cache, refines telemetry deployment detection, updates API security schemes, and includes various stability fixes and documentation improvements. --- **Russian translation:** Это обновление значительно улучшает развертывания с самостоятельным хостингом, в первую очередь обеспечивая полную поддержку S3-совместимых хранилищ с прокси-режимом, включая встроенные MinIO/RustFS оверлеи, и стандартизацию переменных конфигурации S3. Оно также повышает производительность и надежность за счет конфигурирования пула соединений прокси PostgREST, ужесточения политик повторных попыток и оптимизации обновлений панели управления в реальном времени через объединение инвалидаций. Кроме того, релиз устраняет критические проблемы, такие как устаревший кэш учетных данных ИИ, уточняет обнаружение метода развертывания телеметрии, обновляет схемы безопасности API и включает различные исправления стабильности и улучшения документации.

Co-Authored-By: Claude Fable 5 <noreply@anthropic.com> - fix(dashboard): coalesce realtime query invalidations The DATA_UPDATE socket handler invalidated React Query keys synchronously per event, so a burst of writes to a hot table (each POST/DELETE/PATCH/PUT now broadcasts a DATA_UPDATE) triggered one refetch per event against PostgREST — a refetch storm that scales with write volume × open dashboards. Route all invalidations through a coalescing scheduler: keys received within a 300ms window are deduped and flushed as a single batch. Semantics are throttle, not pure debounce — a queued key always flushes within the window, so a continuous write stream keeps the grid live (max staleness ~300ms) while capping refetch rate. The timer is cleared on unmount.
