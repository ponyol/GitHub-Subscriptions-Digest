В этом выпуске представлен новый интерактивный режим симуляции оборудования для оценки соответствия моделей пользовательским спецификациям системы. Веб-интерфейс подвергся значительному обновлению, получив функцию сравнения моделей "бок о бок", 10 новых цветовых тем и улучшенную компонентную архитектуру с расширенной фильтрацией. Основные обновления также включают расширенный каталог моделей (985 моделей), отображение использования дискового пространства и важные исправления, такие как патчи безопасности и более точная оценка памяти для моделей.

Co-Authored-By: gregkh_clanker_t1000 - fix(tui): write dashboard pid file under ~/.llmfit, not /tmp (#324) On Linux, dashboard_pid_path() used std::env::temp_dir() with a fixed filename, /tmp/llmfit-dashboard.pid /tmp is world-writable and the path is fully predictable and std::fs::write follows symlinks, so a local attacker can symlink: ln -s /home/victim/.bashrc /tmp/llmfit-dashboard.pid and the next time the victim launches the TUI, write_dashboard_pid() truncates ~/.bashrc to a small integer. The written content, a pid, is not attacker-controlled, so this is file corruption generally not a nice thing to have happen. macOS ($TMPDIR → /var/folders/.../T/, mode 0700) and Windows (%TEMP% under the user profile) use per-user temp directories and are not affected. Move the pid file under llmfit_core::update::cache_dir() (~/.llmfit on Unix, %APPDATA%\llmfit on Windows) which is user-owned. Bonus of this change is it now keeps all llmfit state located in the same directory as the model cache files, instead of multiple places on the filesystem.
