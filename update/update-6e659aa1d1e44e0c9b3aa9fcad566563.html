Co-Authored-By: Claude Opus 4.8 (1M context) <noreply@anthropic.com> - Merge pull request #12468 from appwrite/feat/coroutine-workers Add coroutine concurrency to queue workers - Lease one broker connection per consume coroutine instead of sharing one The Locking decorator serialized every Redis command on the single consumer connection shared by all consume coroutines. On an idle queue each waiting coroutine holds the mutex for a full 2s blocking pop, so a finished job's completion ops (remove job key, increment stats) starve behind the poppers: a 10ms cache purge took 22-24s to ack, and Storage's testFilePreviewCache observed stale previews because purges landed tens of seconds after enqueue.
