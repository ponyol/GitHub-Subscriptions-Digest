- benchmarks: re-measure the scatter figures on H100 (the qwen3 point was 4 months stale) The README scatter figures dated from 2026-03-15, measured on Apple Silicon with a qwen3 batch+aligner path that no longer exists; they showed qwen3 0.6B at 24.4% WER English / 32.7% French beyond the real-time line. Re-measured on an H100 with the exact same LibriVox samples and the current stack: - qwen3 windowed: 5.2% WER English / 8.6% French at RTF 0.06 - qwen3 causal (English-only): 7.3% WER at RTF 0.06 - stable combos reproduce (fw SS small EN 7.0% = 7.0%; fw SS base FR 18.7% vs 18.8%), so the runs are comparable Raw JSONs and all four charts land in benchmarks/h100_scatter/. The stale, unreferenced benchmarks/h100 and benchmarks/m5 dirs move to benchmarks/archive/ with a provenance note. Bench box gotcha, fixed in the run env only: recent ctranslate2 wheels (4.7/4.8) ship PTX newer than driver 550 can JIT (cudaErrorUnsupportedPtxVersion, surfacing as cudaErrorInvalidDevice on 4.8), silently producing empty transcripts; pinning ctranslate2==4.4.0 with a side-installed cuDNN 8 fixes it. - scatter benchmark: CUDA combo set (faster-whisper + qwen3 streaming), Linux system info The published scatter figures were generated on Apple Silicon with an old qwen3 batch+aligner path that no longer exists. The script now picks a platform combo set: the historical Mac list on darwin, and on CUDA faster-whisper base/small/large-v3-turbo under both policies plus the qwen3-streaming causal (English-only) and windowed towers. Combos can carry extra engine kwargs and a language restriction; system info reads /proc/cpuinfo and nvidia-smi off macOS. - README: feature the research this project is built on - translation: AlignAtt sidecar backend (--translation-backend alignatt) New streaming translation backend backed by Alignatt4LLM's alignatt-mt-server (decoder-only LLM drafts, AlignAtt attention-gated commits, append-only output). The client implements the same duck-typed contract as nllw.OnlineTranslation, so the queue plumbing, timespan alignment and frontend rendering are untouched. The unstable ASR hypothesis tail is forwarded to opted-in translation backends as HypothesisTail snapshots: the MT model drafts over it while only committing against committed words, and the sidecar releases held target tokens on commit without a new MT call. Punctuation boundaries become full-quality utterance re-translations; silence and speaker changes return the streamed partial as the validated segment. Flags: --translation-backend {nllb,alignatt}, --alignatt-url, --alignatt-preset, --alignatt-latency {quality,balanced,low}, --alignatt-context. The qwen3 backends now accept --target-language with the alignatt backend (multilingual output over the English-only causal tower); the in-process NLLB guard stays. Tested against an in-process fake sidecar (12 tests, no GPU), including degradation with the sidecar down, reconnect with accepted-prefix resume, pacing, and the translation_processor plumbing end to end. - docker-image: lowercase the GHCR owner (repository names must be lowercase) - Qwen3 streaming backends (v0.2.23) Qwen3-ASR backends (qwen3-streaming, qwen3-vllm, qwen3-vllm-metal) via the qwen3-asr-causal package, GHCR images, --api-token, per-session language and translation target, frontend auto-reconnect and DOM cap, CORS origins restored, fail-fast on causal + non-0.6B models. - CI: run the test suite; version 0.2.23 The workflow only linted and import-checked while a real pytest suite existed; runs green in 2 min on a bare install with pytest-asyncio. - bound sortformer prediction history on GPU total_preds accumulated every prediction frame for the session lifetime and was copied to the CPU whole on each chunk; only the last chunk's frames are ever read, and speaker continuity lives in the streaming state (spkcache/fifo), not in this tensor. Keep a generous rolling tail (>= 1024 frames) so memory and per-chunk copy cost stop growing with session age - a likely contributor to the >1 min failures in #349. - REST: duration-scaled timeout, HTTP 408 on expiry Fixes #374: /v1/audio/transcriptions used a hardcoded 120 s budget and returned HTTP 200 with empty text on expiry, indistinguishable from silent audio. The budget now defaults to max(120, 2.5x audio duration), is overridable with --rest-timeout, and expiry returns HTTP 408 with an actionable message. - keep full transcript history in mode=full sessions Fixes #372: two pruning layers (TokensAlignment._prune and AudioProcessor._prune_state_tokens, both driven by a hardcoded 300 s retention) silently deleted the earliest lines after ~5 minutes, and mode=full clients - which are resent the whole transcript on every update - lost them permanently. The session mode now reaches AudioProcessor, and retention resolves per session: unlimited for mode=full (and the REST path), 300 s for diff-mode clients that keep their own copy, with an explicit --retention-seconds override (0 = unlimited). Both pruning layers follow the same value. - qwen3-vllm: normalize aligner timestamps, CJK spacing, --vllm-max-model-len Ports the valid parts of PR #375 (thanks @samx81 for the diagnosis): - ForcedAligner configs can declare timestamp_segment_time in milliseconds; normalize at load so aligned word times stay in seconds (fixes second-scale timestamps being off by 1000x). - aligned CJK words join without injected ASCII spaces (empty-word guarded). - new --vllm-max-model-len flag caps the vLLM KV cache on small GPUs instead of the PR's hardcoded 8192 which would override user config. The max_tokens 256->64 change is not taken: 64 tokens can truncate long inference windows; tuning stays user-side via max_tokens. - sortformer local path: log override, widen path heuristic, docstring Follow-ups on PR #378: loading from --sortformer-model-path is now logged (air-gapped users could not tell the default model id was being ignored), relative paths like models/x.nemo fail with a clear file-not-found instead of an HF download error, and the constructor docstring documents the override. - apply PR #376 (docs typo) and PR #378 (sortformer local weights) PR #378 by @felixmr1: --sortformer-model-path accepts a local .nemo file, a directory containing one, or an HF model id. PR #376 by @thsort-dev-agent: Diarization spelling in the alignment principles doc.
