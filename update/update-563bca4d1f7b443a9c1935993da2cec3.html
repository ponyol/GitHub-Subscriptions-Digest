- incus: fix intermittent "incus remote add ... EOF" on start (#1594) Starting the incus runtime sometimes failed with: error starting incus: error running [incus remote add colima unix:///.../incus.sock]: Get "http://unix.socket/1.0": EOF Two independent causes, both confirmed via guest diagnostics: 1. Dead daemon. incus uses systemd socket activation (incus.socket owns /var/lib/incus/unix.socket and activates incus.service). The data disk PreMount stops both units on every boot to mount /var/lib/incus, and after an in-Start VM restart nothing brought them back, so the forwarded host socket had no listener. 2. Stale group membership. usermod adds the lima user to incus-admin, but an existing SSH session (used for the forwarded socket) does not pick up the new group until a fresh login, so the host connection is denied. Fix both: add ensureIncusUp() that (re)starts incus.socket and incus.service, and gate remote setup on a non-root `incus info` from the guest (guestIncusReady) -- which only passes when the daemon is up AND the user is effective in incus-admin. While it fails, restart the VM to refresh the session, bringing the daemon back up after each restart. Also add an on-failure diagnostics step to the incus workflow that dumps guest state (user/groups, incus.service/socket status, socket permissions, sudo/non-sudo incus info, journalctl). Signed-off-by: Eugene Kalinin <e.v.kalinin@gmail.com> - config: reject mount paths containing spaces (#1593) Mount paths with spaces (e.g. "/Volumes/External HD") fail silently: Colima passes the path to Lima correctly, but the unescaped space breaks the generated /etc/fstab entry and the `nofail` option hides the failure, so the volume is never mounted and no error is shown. The real fix belongs upstream in Lima. Until then, validate mounts in ValidateConfig and fail fast with a clear error instead of starting with a silently-broken mount, and document the limitation in the FAQ. The sha512 checksum is still validated after download, so a mirror cannot serve tampered images.
