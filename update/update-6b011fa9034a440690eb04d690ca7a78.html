Это обновление представляет новый пакет `lem-bookmark`. Оно также значительно повышает надежность сборок Nix, исправляя проблемы с получением хеша git и устраняя две критические ошибки сборки Lem через Nix flakes на Linux. В частности, были решены проблемы с компиляцией библиотеки `async-process` и управлением зависимостью `lem-extension-manager` от Quicklisp в изолированных средах, что обеспечивает успешные сборки Nix без влияния на традиционные методы.

- Merge pull request #2006 from mychris/feature/bookmark-extension Adds a new bookmark package. - Fix git hash retrieval during Nix builds - Skip git operations when :nix-build feature is set - Run git command in repository root instead of .git/ directory - Add error handling to prevent build failures when git command fails 🤖 Generated with [Claude Code](https://claude.com/claude-code) Co-Authored-By: Claude <noreply@anthropic.com> - tweak colors - bookmark: Renames the package from bookmark to lem-bookmark. - Fix Nix build failures in flake.nix (#2007) This commit resolves two build failures when building Lem via Nix flakes: 1. async-process library build error: The Makefile referenced a Windows-specific source file (async-process_windows.c) that doesn't exist on Linux, causing make to fail. Added sed command to remove Windows source references and properly build and copy the shared library. 2. lem-extension-manager QL-DIST dependency: The extension manager depends on Quicklisp's QL-DIST package which is unavailable in Nix's sandboxed build environment. Introduced a :nix-build feature flag that conditionally excludes lem-extension-manager during Nix builds while preserving it for standard builds. These changes enable successful Nix flake builds on Linux without affecting traditional build methods (Roswell, qlot, manual builds).
