Это обновление значительно повышает производительность за счет снижения потребления GPU, внедрения двухфазного префилла для гибридных моделей (Qwen3.5) и многоуровневого KV-кэша с O(1) потоковым декодированием, что резко сокращает время до первого токена (TTFT). Также улучшена интеграция инструментов, включая переключатель "Disable Tools" и детерминированный порядок, что в сочетании с другими исправлениями повышает повторное использование KV-кэша за счет предотвращения расхождения промптов. Кроме того, выпуск включает различные улучшения качества кода, доработки пользовательского интерфейса, такие как индикатор прогресса префилла, и основные архитектурные обновления для надежности локального вывода и совместимости со Swift 6.

The chat template appends a generation-prefix token sequence (e.g. '<|im_start|>assistant\n<think>\n') after the last user turn. This prefix is present in the cache from the prior turn but absent in the prompt for the next turn, causing commonPrefix to diverge ~5 tokens before cacheOffset. toTrim = 5 > 0, MambaCache.isTrimmable = false → full re-prefill every turn (~76s on Qwen3.5-9B). Fix: split prefill into two phases separated at the stable boundary (last user message, before gen-prefix): Phase 1: process all tokens up to stableBoundary with model.prepare() (resets precomputedPositionIds / ropeDeltas for VLMs, prevents position-state corruption in subsequent turns). Snapshot: deep-copy cache at stableBoundary and return it alongside the final prompt tokens as GenerationResult.snapshotCache / .snapshotTokens. Phase 2: process remaining tokens (gen-prefix) then begin generation. ModelRuntime stores the stable-boundary snapshot instead of the full- prompt snapshot so the next turn's common-prefix hits exactly at cacheOffset with toTrim == 0. Guard: useTwoPhase requires existingCache != nil to skip Phase 1 on the first turn (avoids doubling peak RAM with the initial system-prompt prefill). On T1 the single-phase path runs; two-phase activates from T2. Generation loop uses a manual AsyncStream instead of TokenIterator.init because TokenIterator.init calls model.prepare() which would overwrite the Phase-1 position state. Benchmark on M4 Pro 64GB (3-turn, non-trivial prompts): Qwen3.5-9B-MLX-4bit T2 TTFT: 76 000ms → 3 689ms (~20x improvement) Qwen3.5-27B-4bit T2 TTFT: ~120 000ms → 8 490ms (~14x improvement) Non-hybrid models (Phi-4, GLM-4) unaffected (single-phase trim path). - perf: tiered KV cache store, O(1) streaming decode, eval fix KVCacheStore gains a two-tier (hot RAM / cold SSD) architecture. Hot entries are kept up to a model-size-derived RAM budget; entries that are evicted from RAM are serialised to SSD in a background task and rehydrated on the next turn. Access order is maintained by an O(1) doubly-linked LRU list so eviction is never O(n). StreamAccumulator gains an O(1) sliding-window decode path: instead of re-decoding the entire token history on every new token (O(n²) total), only the net-new suffix is decoded per step (O(n) total). os_signpost intervals bracket each accumulate() call for easy Instruments profiling. ModelRuntime gains three correctness fixes: 1. eval() is called on cache arrays in storeSessionCache and buildPrefixCache. TokenIterator leaves MLX graph nodes in the cache that cause the engine to re-walk the full computation graph on the next turn; forcing materialisation here makes subsequent reads O(1). 2. buildPrefixCache / generateEventStream use the new GenerationResult struct returned by MLXGenerationEngine (removes positional tuple). 3. Cache snapshot moved to pre-generation (immediately after prefill, before any tokens are generated), replacing the post-generation wrapWithCacheStore approach. A post-generation snapshot offsets the cache by (promptTokens + generatedIds), causing the common-prefix to diverge on the next turn and requiring trim; the pre-generation snapshot eliminates that divergence for both single- and two-phase paths.
