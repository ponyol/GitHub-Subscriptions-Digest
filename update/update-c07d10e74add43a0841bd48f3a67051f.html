- feat: add partial callback for real-time ghost text (#230) ## Why is this change needed? I have a use case where I need to show streaming speech to text as it lands. Currently there's no partials for me to latch onto in the `StreamingEouAsrManager`. This adds that support; tested and using successfully on this fork. https://github.com/user-attachments/assets/5c1f1d49-0f10-4a93-8eaa-4d35338a4b0f ## Summary Add `setPartialCallback()` to `StreamingEouAsrManager` that fires after each chunk with the current accumulated transcript. This enables real-time "ghost text" display during speech - useful for live transcription UIs that want to show text as it's being spoken before the utterance is finalized. ## Changes - Add `PartialCallback` type alias (matching existing `EouCallback` pattern) - Add `partialCallback` private property - Add `setPartialCallback(_:)` public method - Invoke callback after each chunk's token accumulation in `processChunkAndDecode()` ## Usage ```swift await manager.setPartialCallback { transcript in // Update UI with partial transcript (ghost text) print("Partial: \(transcript)") } ``` The callback receives the full accumulated transcript after each 320ms chunk is processed, allowing UIs to display evolving text before EOU is detected. --------- - feat: Support emitting transcription progress percentage (#229) Resolve https://github.com/FluidInference/FluidAudio/issues/228 --------- - Fix: Use async prediction API in segmentation prewarm to prevent hang (#227) ## Summary The synchronous `MLModel.prediction(from:options:)` call in `prewarmSegmentationModel()` can hang indefinitely on macOS when the Neural Engine (ANE) is contended after model compilation. ## Problem When running FluidAudio's offline diarization on macOS, the process hangs at 0% CPU after the Segmentation model is compiled: ``` [INFO] Compiled model Segmentation.mlmodelc in 334.48 ms <hangs indefinitely> ``` The root cause is the synchronous prediction call in `prewarmSegmentationModel()`: - `MLModel.prediction(from:options:)` blocks until ANE resources are available - After model compilation, the ANE may be in a contended state - No timeout mechanism exists for synchronous prediction - The process hangs indefinitely waiting for ANE ## Solution Convert `prewarmSegmentationModel()` to use the async prediction API introduced in iOS 17 / macOS 14: ```swift // Before (hangs) private func prewarmSegmentationModel(_ model: MLModel) throws { _ = try model.prediction(from: provider, options: options) } // After (yields properly) private func prewarmSegmentationModel(_ model: MLModel) async throws { _ = try await model.prediction(from: provider, options: options) } ``` Benefits of async prediction: - Yields while waiting for ANE resources instead of blocking - Supports task cancellation - Prevents deadlocks during model initialization - Thread-safe and integrates with Swift concurrency ## Testing Tested on: - macOS 26.1 (Tahoe) with Apple M4 Pro - The hang was reproducible before the fix - After the fix, model initialization completes successfully ## References - [WWDC23: Improve Core ML integration with async prediction](https://developer.apple.com/videos/play/wwdc2023/10049/) - [Hugging Face: Async Core ML inference](https://huggingface.co/docs/swift-transformers/async-inference) Co-authored-by: Alex <36247722+Alex-Wengg@users.noreply.github.com> - Content skipping bug fix (#223) - Fixed a bug where some content got skipped in longer videos. - Cause: Chunk sizes were not divisible by the encoder frame size which caused the merging to skip some audio because the remainder was not accounted for in the integer division. - Solution: Made it so that 14.96 seconds of audio was collected i(nstead of 14.99 seconds) to ensure that the start of every chunk is aligned with the start of every frame. - Resolve #212 - added --output-json to CLI transcribe (#222) - Added --output-json to transcribe command to make it possible to merge text with speaker segments using CLI.
