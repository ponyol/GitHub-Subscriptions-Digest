RAGFlow has integrated OpenDataLoader as a new, optional PDF parsing backend. This addition provides users with a deterministic, local-first alternative offering competitive table extraction accuracy, and can be significantly faster than existing parsers like Docling. The update also includes various bug fixes, API refactorings, and support for new AI model providers and features across the platform. --- RAGFlow интегрировал OpenDataLoader в качестве нового, опционального бэкенда для парсинга PDF. Это предоставляет пользователям детерминированную, локальную альтернативу с конкурентной точностью извлечения таблиц, которая может быть значительно быстрее существующих парсеров, таких как Docling. AD ### Type of change - Fix: serialize GraphRAG entity resolution merges to avoid graph mutation races (#14237) ### What problem does this PR solve? This PR fixes the merge-phase crash reported in #14236 during GraphRAG entity resolution. The issue happens after candidate pair resolution completes, when multiple merge coroutines mutate the same shared `networkx` graph concurrently. In `_merge_graph_nodes`, the code iterates over `graph.neighbors(node1)` and also awaits during edge/description merging. That allows another coroutine to modify the graph adjacency structure in between, which can trigger `RuntimeError: dictionary keys changed during iteration` and can also lead to unsafe shared-graph mutation. This change keeps the PR scoped to that single issue by: - serializing merge-time graph mutations with a dedicated merge lock - snapshotting `graph.neighbors(node1)` with `list(...)` before iteration Together, these changes prevent concurrent mutation of the shared graph during the merge phase and make the merge loop safe against live-view invalidation.
