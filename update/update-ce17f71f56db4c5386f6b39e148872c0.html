Суммаризация (на русском)

This update for Milvus includes critical bug fixes addressing server crashes during GROUP BY aggregations with empty results and division-by-zero errors in filter expressions, along with corrections for three-valued logic in expression evaluation. Significant performance enhancements have been implemented, such as optimizing delete snapshot operations and prepared geo queries for speedups of up to 37x and 15x respectively, alongside substantial reductions in Python test log sizes and memory allocations. The release also features refactored thread pool usage for improved concurrency, support for nested indexes, and a version bump to v2.6.10. --- Это обновление Milvus включает критические исправления ошибок, устраняющие сбои сервера во время агрегаций GROUP BY с пустыми результатами и ошибки деления на ноль в выражениях фильтров, а также корректировки трехзначной логики при вычислении выражений. Были реализованы значительные улучшения производительности, такие как оптимизация операций удаления снимков и подготовленных гео-запросов для ускорения до 37 и 15 раз соответственно, наряду с существенным сокращением объемов логов Python-тестов и выделения памяти. Релиз также включает рефакторинг использования пулов потоков для улучшения параллелизма, поддержку вложенных индексов и обновление версии до v2.6.10.

When filter matches 0 rows, no data flows to AggregationNode 3. `addInputForActiveRows()` is never called 4. `hash_table_` remains `nullptr` 5. `getOutput()` directly accesses `hash_table_->rows()` → **SIGSEGV** **Inconsistency:** Global aggregation (no GROUP BY) has lazy initialization via `initializeGlobalAggregation()`, but non-global aggregation (with GROUP BY) lacks this fallback mechanism. ## Solution Add lazy initialization in `getOutput()` to ensure `hash_table_` is always initialized before access, even when there's no input data: ```cpp bool GroupingSet::getOutput(milvus::RowVectorPtr& result) { if (isGlobal_) { return getGlobalAggregationOutput(result); } // Ensure hash_table_ is initialized even when there's no input data // This handles the case where filter matches zero rows if (!hash_table_) { createHashTable(); } AssertInfo(hash_table_ != nullptr, "hash_table_ should not be nullptr after initialization"); const auto& all_rows = hash_table_->rows()->allRows(); // Now safe if (!all_rows.empty()) { extractGroups(result); return true; } return false; // Empty result } ``` This approach: - ✅ Matches the lazy initialization pattern used by global aggregation - ✅ Minimal code change (4 lines added) - ✅ No performance impact on normal queries - ✅ Handles the empty result edge case safely ## Testing ### Verification -
