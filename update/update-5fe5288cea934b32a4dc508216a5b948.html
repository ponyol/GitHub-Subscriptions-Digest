Суммаризация (на русском)

This update delivers substantial stability and performance improvements, particularly for `langgraph` and `ADK middleware`. `Langgraph` now features more robust handling of JSON parsing failures in tool calls and resume inputs, with enhanced error reporting and improved interrupt/resume lifecycle management. A major `ADK middleware` refactor addresses stale session write errors and optimistic concurrency issues, significantly boosting streaming fidelity for Human-in-the-Loop (HITL) scenarios by deferring only relevant events. Additionally, the release introduces a new Cloudflare Agents integration and updates CI/CD for npm authentication. --- **Russian Translation:** Это обновление обеспечивает существенные улучшения стабильности и производительности, особенно для `langgraph` и `ADK middleware`. `Langgraph` теперь предлагает более надежную обработку ошибок парсинга JSON в вызовах инструментов и входных данных для возобновления, с улучшенным протоколированием ошибок и управлением жизненным циклом прерывания/возобновления. Крупный рефакторинг `ADK middleware` устраняет ошибки записи устаревших сессий и проблемы контроля оптимистической конкуренции, значительно повышая точность стриминга для сценариев Human-in-the-Loop (HITL) за счет отложенной обработки только соответствующих событий. Кроме того, релиз включает новую интеграцию Cloudflare Agents и обновляет CI/CD для аутентификации npm.

This PR moves the HITL persistence step producer-side and defers ONLY the HITL ``ToolCallEndEvent`` itself. All other events (non-HITL tool calls, text deltas, backend ``ToolCallResultEvent``s) stream through the underlying queue unblocked. Mechanism: * New ``_HitlDeferringQueue`` (subclass of ``asyncio.Queue``) replaces the bare queue created in ``_start_background_execution``. On ``put``: - HITL ``ToolCallEndEvent`` whose id is in ``long_running_tool_ids`` → buffered in a local dict instead of the inner queue. - ``ToolCallResultEvent`` for a deferred id → release the buffered TCE first (preserves TCE→Result order on the wire) and remove the id from the deferred set (no client continuation → no need to persist). - ``None`` sentinel → implicit ``flush_deferred`` first, then put None so the consumer sees deferred TCEs before the stream ends. - Anything else → passthrough. * ``_run_adk_in_background`` calls ``_finalize_hitl_buffer`` (new helper that iterates ``deferred_hitl_ids`` and calls ``_add_pending_tool_call_with_context`` for each) at all three exit points: just before the normal-exit ``put(None)``, before the LRO drain ``return``, and before the non-resumable LRO ``return``. Each is followed by ``await event_queue.put(None)`` so the deferring queue flushes via its ``put(None)`` override. * ``_run_new_execution`` no longer needs the ``await execution.task`` / ``_add_pending_tool_call_with_context`` block on HITL TCE — by the time the consumer observes a TCE, the producer has already persisted (or it was a non-HITL TCE that doesn't need persistence).
