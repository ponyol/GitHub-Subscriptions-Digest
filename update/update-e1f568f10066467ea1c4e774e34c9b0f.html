Суммаризация (на русском)

Этот выпуск обеспечивает значительный прирост производительности благодаря оптимизированным операциям ядра, включая планировщик с перекрытием для сгруппированного умножения матриц NVFP4 (ускорение в 1,047 раза по среднему геометрическому), новое нативное блочно-масштабированное умножение матриц MXFP4 для AMD CDNA4 и объединенные операции ядра для повышения эффективности. Основные архитектурные обновления включают новую систему диспетчеризации SPMD на основе правил для распределенных операций, консолидацию типов входных данных KVCache с использованием дженериков и модульную структуру API `Atomic`, а также значительный рефакторинг основных компонентов, таких как трансформатор Wan. Улучшения для разработчиков включают поддержку `syncscope` для `pop.store` и `Atomic.store` для предотвращения избыточной синхронизации, добавление индикаторов выполнения для захвата графов CUDA и исправление различных проблем с загрузкой весов моделей и ошибок производительности (например, улучшение задержки декодирования Eagle в 2-3 раза).

It added ~700 ns of pipeline bubble per tile in the critical path (TMA load + MMA), blocking the drain of tile N from overlapping with the fill of tile N+1. The fix is to move the scheduler to a dedicated warp that publishes the next tile into a 2-slot SMEM ring while the consumers are still draining the current one. Inter-tile pipeline overlap is the whole point of a persistent kernel, and this finally lets it happen. For first-tile latency, iter 0 on each consumer still uses the old-style inline scan + warp.broadcast, so nobody waits on the scheduler's first publication. On Kimi K2.5 (B200, 16 shapes, best-of-3), 16/16 shapes are faster than main with a 1.047× geomean.
