The skill suggests omitting `start_offset` to refresh all data, but the API requires explicitly passing `NULL`. ### Issue 2: Duplicate Columnstore Policy **Source**: Tiger skill documentation (setup-timescaledb-hypertables/SKILL.md:45-48) **Tiger Skill Suggested**: ```sql -- In CREATE TABLE ) WITH ( ... tsdb.enable_columnstore=true, ... ); -- Then separately (Step 2) CALL add_columnstore_policy('sensor_data', after => INTERVAL '1 day'); ``` **Error Encountered**: ``` ERROR: columnstore policy already exists for hypertable or continuous aggregate "sensor_data" HINT: Set option "if_not_exists" to true to avoid error. ``` **Root Cause**: The `tsdb.enable_columnstore=true` option in `CREATE TABLE` automatically creates a columnstore policy with default settings (7 days). Calling `add_columnstore_policy()` again creates a duplicate. **Resolution**: Comment out the manual `add_columnstore_policy()` call since it's auto-created: ```sql -- Note: Columnstore policy is auto-created by tsdb.enable_columnstore=true -- CALL add_columnstore_policy('sensor_data', after => INTERVAL '1 day'); ``` ### Issue 3: Deprecated View Names **Source**: Tiger skill documentation mentions deprecated vs new view names **Attempted**: ```sql SELECT * FROM timescaledb_information.columnstore_settings; SELECT * FROM timescaledb_information.hypertable_columnstore_stats; ``` **Error**: ``` ERROR: relation "timescaledb_information.columnstore_settings" does not exist ERROR: relation "timescaledb_information.hypertable_columnstore_stats" does not exist ``` **Root Cause**: The new views mentioned in the skill documentation (API Reference section) are not available in TimescaleDB 2.24.0 yet, or have different names. **Resolution**: Use the function-based API instead: ```sql SELECT * FROM hypertable_compression_stats('sensor_data'); -- Works correctly and returns compression statistics ``` ### Issue 4: convert_to_columnstore is a Procedure, Not a Function **Source**: Tiger skill documentation (setup-timescaledb-hypertables/SKILL.md:430-439) **Attempted**: ```sql SELECT convert_to_columnstore('_hyper_7_1_chunk'); ``` **Error**: ``` ERROR: convert_to_columnstore(unknown) is a procedure HINT: To call a procedure, use CALL. ``` **Resolution**: ```sql CALL convert_to_columnstore('_timescaledb_internal._hyper_7_1_chunk'); ``` Also needed to use fully-qualified chunk name with schema prefix `_timescaledb_internal.`. - Refactor: Consolidate search tools and enable BM25 for Postgres docs (#68) ## Summary This PR unifies the disparate search tools (semantic/keyword for Tiger/Postgres) into a single `search_docs` tool, simplifying the API surface.
