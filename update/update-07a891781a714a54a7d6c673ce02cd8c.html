Суммаризация (на русском)

Данное обновление активирует захват графа CUDA для провайдера выполнения CUDA, который ранее был заблокирован принудительно. Это значительно улучшает пропускную способность декодирования на 20-45% (и до 47% в некоторых случаях) для различных размеров моделей Qwen3.5 за счет устранения избыточных затрат на запуск ядер для каждого токена. Ключевые изменения включают удаление блокирующего исключения, обеспечение активации захвата графа только для сеансов декодирования, чтобы предотвратить сбои при работе с моделями динамической формы, а также доработку управления рекуррентным состоянием для совместимости с графами CUDA.

- Enable CUDA graph capture for CUDA EP to improve decode throughput (#2070) ## Enable CUDA graph capture for CUDA EP to improve decode throughput ### Summary Enable CUDA graph capture for the CUDA execution provider, which was previously blocked with a hard exception. This eliminates per-token kernel launch overhead during the decode phase, improving throughput by **20-45%** across Qwen3.5 model sizes (0.8B through 9B). ### Changes #### 1. `src/config.cpp` Remove the exception that blocked `enable_cuda_graph=1` for CUDA EP. Instead of throwing, return `true` to enable graph capture — matching the behavior already implemented for DML and NvTensorRtRtx providers. #### 2. `src/cuda/session_options.cpp` Make CUDA's `AppendExecutionProvider` respect the `disable_graph_capture` parameter (previously ignored). When `disable_graph_capture=true` (used for vision and embedding sessions), force `enable_cuda_graph` to `"0"` in the provider options. This ensures CUDA graph is only enabled on the decoder session, preventing crashes from dynamic-shape vision/embedding models. #### 3. `src/models/recurrent_state.cpp` Fix `RecurrentState::Update()` for CUDA graph compatibility. The original code used `std::swap` to alternate past/present buffers each decode step, which changes memory addresses and invalidates the captured CUDA graph. When graph capture is enabled, copy present→past in-place instead, preserving the stable pointers that the CUDA graph expects. ### Performance Results (A100, Qwen3.5 INT4, 256 tokens, greedy) | Model | Before | After | Improvement | |-------|--------|-------|-------------| | 0.8B | 166 t/s | 244 t/s | **+47%** | | 2B | 141 t/s | 195 t/s | **+38%** | | 4B | 94 t/s | 120 t/s | **+28%** | | 9B | 76 t/s | 93 t/s | **+22%** | ### Testing -
