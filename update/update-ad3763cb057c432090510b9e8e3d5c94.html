Суммаризация (на русском)

Версия 1.8.2 содержит исправления для двух проблем. Она устраняет сбои, вызванные минимальными пользовательскими записями моделей в `models.json`, путем автоматического заполнения отсутствующих полей для `llama-cpp-provider`. Кроме того, исправлена некорректная инъекция параметра `temperature=0.3` во все запросы завершения чата путем ограничения его использования только для определенных локальных провайдеров, таких как llamacpp, ollama и lmstudio. Эти изменения являются чистыми дополнениями и не вносят критических изменений в CLI, настройки или публичный API.

Исходный текст

- v1.8.2: tolerate minimal user models.json, gate temperature on local providers Fixes two GitHub issues that surfaced this week: - #36 — A user-override models.json with a minimal model entry (just id/contextWindow/input/reasoning, no name/maxTokens/cost) crashed pi at startup with `Cannot read properties of undefined (reading 'input')`, because pi's registry stored the entry verbatim and later tried to read model.cost.input deep in applyModelOverride. llama-cpp-provider now fills the same defaults pi uses for built-in models, so a minimal entry just works; user-supplied values still win, unknown fields are preserved, and a missing id is flagged in the source diagnostics instead of crashing pi. - #33 — benchmark-profiles' default_model_profile.temperature=0.3 was being injected into every chat-completions payload, including Copilot GPT-5.x / OpenAI o-series, which 400 on the parameter. Temperature injection is now gated by provider: on for llamacpp/ollama/lmstudio (the providers it was tuned for), off for everything else. LITTLE_CODER_TEMPERATURE_PROVIDERS replaces the default list when you bring your own local provider. Both fixes are pure additions: no CLI / settings / public-API changes, all 231 vitest tests pass (16 new), tsc --noEmit clean. Co-Authored-By: Claude Opus 4.7 (1M context) <noreply@anthropic.com>
