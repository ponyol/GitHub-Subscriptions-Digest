Суммаризация (на русском)

Проект обновил свою зависимость MLX до версии 0.30.1+, что позволило использовать RDMA через Thunderbolt и распределенные вычисления, а также исправило соглашения об именовании координаторов. Были реализованы критические исправления для приложений macOS, упакованных с помощью PyInstaller, устраняющие сбои многопроцессорности и бесшумные ошибки загрузки моделей, важные для запуска экземпляров. Дополнительно обновление включает соответствие спецификации XDG Base Directory, улучшенные процессы сборки, исправления порта API и надежную проверку SSL-сертификатов. Документация также была дополнена информацией о предварительных требованиях и архитектурных деталях.

[0] https://github.com/exo-explore/exo/actions/runs/20467656904/job/58815275013 - exo: handle -c flag for multiprocessing helpers in frozen apps When Python's multiprocessing spawns child processes on macOS (using the "spawn" method), it also spawns helper processes like the resource tracker by executing: ./frozen_app -c "from multiprocessing.resource_tracker import main; main()" A frozen PyInstaller app doesn't understand `-c` natively - it just runs main(). This causes the resource tracker to fail silently. This adds a minimal `-c` handler that intercepts the flag, extracts the inline code, and exec()s it before main() runs. This is required for the Process() spawn in runner_supervisor.py to work correctly in the DMG. Note that the pyinstaller docs say `freeze_support` is supposed to make this work, but it doesn't.
