Это обновление добавляет возможность пропускать файлы и сайты SharePoint на основе меток конфиденциальности Microsoft Purview, улучшая фильтрацию данных для источников SharePoint и OneDrive. Оно также включает важные исправления, предотвращающие сбои задач синхронизации из-за непредвиденных именованных аргументов при воспроизведении ARF и корректно классифицирующие ошибки, вызванные действиями пользователя (например, истекшие учетные данные), как неопасные, а не как системные сбои рабочего процесса. Эти изменения повышают стабильность системы, обеспечивают более точные метрики мониторинга и улучшают обработку и отчетность по проблемам, связанным с пользователями.

- fix(arf): accept sync pipeline kwargs in ArfReplaySource.generate_entities (#1791) SyncFactory._build_stream always calls source.generate_entities with cursor=, files=, node_selections=. ArfReplaySource declared no kwargs, so any replay sync_job (triggered by execution_config.behavior.replay_from_arf=true) fails immediately with TypeError: got an unexpected keyword argument 'cursor'. Widen the signature to accept and ignore the three standard kwargs — replay reads from ARF storage, not a live source, so they're irrelevant. Caught while building the two-stack migration integration test in airweave-migrations; without this, the dst-side replay never produces entities. - feat(sharepoint, onedrive): skip files/sites by Purview sensitivity label (#1790) * feat(sharepoint, onedrive): skip files/sites by Purview sensitivity label Adds excluded_sensitivity_label_ids, skip_encrypted_files, and skip_unlabeled_files to the SharePoint, SharePoint Online, and OneDrive source configs. Files carrying any blocked label are skipped via extractSensitivityLabels per item. For SharePoint sources, the same list is matched against the M365 Group's assignedLabels so whole sites can be short-circuited before walking their drives.
