Co-Authored-By: Claude Opus 4.6 (1M context) <noreply@anthropic.com> - fix(lsp): omit optional Content-Type header from outgoing messages (#1442) Per the LSP spec, Content-Type is optional and defaults to application/vscode-jsonrpc; charset=utf-8 (the exact value we were sending). Spec-compliant servers behave identically with or without it. In practice some servers have stricter parsers. Notably, Godot's GDScript LSP (LSPeer::handle_data in modules/gdscript/language_server/gdscript_language_protocol.cpp) extracts the body length via header.substr(16).to_int() and silently drops messages that contain any header beyond Content-Length. Sending only Content-Length is interoperable across the spec-compliant servers we use today and unblocks Godot's LSP. Also tightens the type signature of create_message from tuple[bytes, bytes, bytes] to tuple[bytes, bytes] now that there is no Content-Type element.
