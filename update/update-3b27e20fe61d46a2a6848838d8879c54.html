- chore: bump version to 0.4.23 - fix: harden ingest and scheduled import flows - fix: support doubao embeddings - Merge pull request #358 from kostadis/fix-dedup-runaway-hardening fix: stop the duplicate scan hanging to the 30-min backstop ("request cancelled") - Merge pull request #357 from dake6767/fix/codex-cli-node-path fix: pass login shell PATH to spawned codex CLI so its node shebang resolves - fix: rebuild embedding chunks safely - release: v0.4.22 - fix: stop dedup scan hanging to the 30-min backstop ("request cancelled") The "Scan for duplicates" maintenance feature could hang until the 30-min streaming backstop fired and then surface a bare "request cancelled" with no guidance. Two independent gaps caused it; this fixes both. 1. The dedup LLM call never bounded its work. `buildDedupLlmCall` was the only structured-output caller that passed neither `reasoning: { mode: "off" }` nor a `max_tokens` cap (every other structured caller — ingest, connection-tests, vision-caption, anytxt-search — passes both). On a reasoning-capable model (an Ollama thinking model, or an unrecognized reasoning model behind a custom endpoint) the scan spent its whole budget on chain-of-thought, emitted no content, and ran the stream to the 30-min backstop. Now it disables thinking and caps output, with a required per-call-site `maxTokens` so detection (small JSON list) and merge (a complete rewritten page) get appropriate budgets and merges are never truncated. 2. The backstop's mid-stream abort surfaced as a raw string. When the timeout fires during streaming, the Tauri HTTP plugin tears the body stream down with a bare string "Request cancelled" (not an Error). streamChat's streaming-path catch only matched `err instanceof Error`, so it skipped the friendly "Request timed out after 30 min…" mapping the pre-fetch catch already had and leaked the raw string. It now recognizes the string/Error/AbortError abort shapes and maps a fired backstop to the actionable timeout message (else a silent user-cancel). Adds focused unit tests for both: that the dedup wrapper forwards reasoning-off and the caller's max_tokens, and that a mid-stream string abort maps to the timeout message when the backstop fired (silent onDone otherwise). Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com> - fix: pass login shell PATH to spawned codex CLI so its node shebang resolves `codex` is distributed as a Node script with a `#!/usr/bin/env node` shebang. We already resolve the codex *binary* via the login shell PATH (cli_resolver falls back to it when the GUI launch's minimal PATH can't find the command). But when we actually spawn codex, the child inherits that same minimal PATH — which under a macOS Finder/Dock launch omits version-manager dirs (nvm, etc.). So codex starts, its shebang runs `/usr/bin/env node`, node isn't on PATH, and the process dies with: env: node: No such file or directory Detection therefore reports codex as not installed even though it runs fine from a terminal. Fix: add `child_path_env()` to cli_resolver — it reuses the cached login shell PATH (the same one used to locate the binary) and prepends it to the inherited PATH. `codex_cli_detect` and `codex_cli_spawn` set this as the child's PATH so the shebang finds node. No-op on Windows and when there's nothing to add.
