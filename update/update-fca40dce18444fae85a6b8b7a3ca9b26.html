Суммаризация (на русском)

Последние обновления Faiss в основном направлены на повышение производительности и дальнейшую интеграцию поиска по разреженным векторам (SVS). Ключевое улучшение производительности включает встраивание вычислений расстояния для устранения регрессии, что принесло пользу нескольким типам индексов. Множество изменений связаны с SVS, включая включение его в качестве внутренней зависимости, переход на пакет conda для его выполнения и добавление инструментов для сравнения размера его бинарного файла. Кроме того, было улучшено качество кода за счет исправления ошибок линтинга и усовершенствования тестов корректности скалярного квантователя.

- inline scanning code for fast distance computations (#4785) Summary: Pull Request resolved: https://github.com/facebookresearch/faiss/pull/4785 After the ResultHandler diff landed there was a 1% performance regression on some critical codepath. It seems plausible that this regression was caused because the inner loop of the scanning code calls 2 virtual functions: - distance_to_code to compute a code distance - add_result to update the result structure whenever a better restlt is found It is probably the distance_to_code function that is the culprit because it is called for *all* the codes, when distance_to_code is called only if a better rresult is found. What this diff changes is that the scanning code is made available to the InvertedListScanner implementation so that the distance computation inlining can happen. This is applied to IndexIVFScalarQuantizer, IndexIVFFlat and IndexIVFRabitQ (it turns out that this one has a virtual function call inside its ditance_to_code so this update is unlikely to be significant).
