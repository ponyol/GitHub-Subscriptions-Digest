Суммаризация (на русском)

Этот выпуск в основном сосредоточен на улучшении компонента `jailer` за счет усовершенствованной функции копирования бинарных файлов, строгого запрета ссылок в целевых путях и обеспечения согласованного владения файлами, дополненного новыми интеграционными тестами. Также исправлена проблема тестового фреймворка, связанная с разрешением путей к артефактам, и включены важные обновления зависимостей для `urllib3` и множества пакетов, связанных с Firecracker. Наконец, функциональность "boost" повторно включена для систем AMD для оценки долгосрочной стабильности.

- chore(changelog): add new entry Add entry about new Jailer changes Signed-off-by: Egor Lazarchuk <yegorlz@amazon.co.uk> - fix(jailer): update binary copy function The default `fs::copy` does not allow fine grain control over the way src and dst files are open and copied, so implement more direct approach specifying only parameters which are needed for the copy and further jailer operation. While at it, deny any links at a destination path for the binary copy since such usecases are not supposed to be used with the Jailer. Also change the owner of the binary file to the specified uid/gid, to keep all files in the jail consistent in ownership. Additionally add an integration test to ensure symlinks and hardlinks are not allowed as a destination path. Signed-off-by: Egor Lazarchuk <yegorlz@amazon.co.uk> - fix(test framework): fix local path to artifacts When python tests like `test-popular-containers` is run, it will use local path to artifacts which is determined by reading `build/current_artifacts` file. This file will contain path in form `build/artifacts/...`. The problem was that the `LOCAL_BUILD_PATH` also containers `/build` in the path, so when both are concatenated, it results in the invalid path. Fix this by using `FC_WORKSPACE_DIR` directly.
