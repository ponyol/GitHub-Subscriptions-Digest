The update significantly enhances shard pruning by enabling it for `IN-subqueries` and `literal tuple-IN` conditions, using early materialization and rewriting via the new `optimize_skip_unused_shards_with_subqueries` setting. Key improvements include robust handling of `NULL` values, strict conjunctive position requirements for empty `IN` conditions, and on-demand subquery materialization to optimize query execution. The changes also introduce comprehensive hardening, such as enforcing subquery depth limits, capping materialized set sizes, and deduping tuple-IN values, alongside extensive testing and improved error handling for greater stability. --- **Russian translation:** Обновление значительно улучшает обрезку шардов, позволяя применять ее к `IN-subquery` и `literal tuple-IN` условиям с помощью ранней материализации и переписывания через новую настройку `optimize_skip_unused_shards_with_subqueries`. Ключевые улучшения включают надежную обработку значений `NULL`, строгие требования к конъюнктивной позиции для пустых условий `IN`, а также материализацию подзапросов по требованию для оптимизации выполнения запросов. Изменения также вводят комплексные усиления, такие как контроль глубины подзапросов, ограничение размеров материализуемых наборов и дедупликация значений в `tuple-IN`, наряду с обширным тестированием и улучшенной обработкой ошибок для повышения стабильности.
