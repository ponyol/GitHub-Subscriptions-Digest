Суммаризация (на русском)

This release delivers significant performance enhancements, particularly through kernel optimizations for AMD MXFP4 GEMM and SM100 FlashAttention, including new FP8 support for MHA prefill and decode. It expands model capabilities by integrating DeepSeekV3 architecture, improving Kimi K2.5's grammar enforcement, and adding comprehensive tool call schema support for Gemma4. The MAX framework also benefits from enhanced profiling, improved speculative decoding stability, streamlined sharding internals, and various tooling and documentation updates. --- **Русский перевод:** Этот выпуск содержит значительные улучшения производительности, особенно за счет оптимизации ядер для AMD MXFP4 GEMM и SM100 FlashAttention, включая новую поддержку FP8 для предварительной обработки и декодирования MHA. Он расширяет возможности моделей, интегрируя архитектуру DeepSeekV3, улучшая применение грамматики Kimi K2.5 и добавляя комплексную поддержку схем вызовов инструментов для Gemma4. Фреймворк MAX также выигрывает от улучшенного профилирования, повышенной стабильности спекулятивного декодирования, оптимизированной внутренней структуры шардирования и различных обновлений инструментов и документации.

MODULAR_ORIG_COMMIT_REV_ID: 4ad4e71dc873da1a339536d66893abe71b11cd05 - [kernels] skip scale smem staging (#87341) Before this PR, Scales were stored in a plain row-major format. This row major format causes issues since the TV layout was column major. This led to us staging scales in shared memory, so that it can be read coalesced from HBM, and read in column major from smem. This was inefficient because it required a extra roundtrip from smem, and because it didn't take advantage of the OP_SEL. MFMA cores have an OP_SEL feature that allows a MFMA to read a specific byte from a 32 bit register, (each byte representing a unique scale). So with this we could provide scales for 128 fp4 elements using one packed 32 bit register. To solve these problems, we shuffle the scales using a packed layout that ensures scales are read coalesced and in the proper thread layout that avoids shared memory staging. To do this we shuffle the B scales during weight initialization, and create a kernel that shuffles before every grouped gemm call.
