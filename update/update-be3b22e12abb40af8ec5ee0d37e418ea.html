MODULAR_ORIG_COMMIT_REV_ID: a9ffdf5071bdfe5a5d6b3aa8f1cc5fe09d753d49 - [stdlib] polish: Use `ImplicitlyDestructible` in bounds that actually require `__del__()` Currently, `ImplicitlyDestructible` is an alias for `AnyType`, which requires `__del__()`. However, before long, `AnyType` should truly be any type, and `ImplicitlyDestructible` should be an independent trait. To get ready for splitting `__del__()` off of `AnyType`, update bounds that today take `AnyType` and whose implementations *actually* require being able to call `__del__()` to instead write out `ImplicitlyDestructible`. This will reduce churn when `AnyType` is actually changed. A good example of a type that actually requires `ImplicitlyDestructible` is `struct PyMojoObject[T: ImplicitlyDestructible]`, which needs to be able to destroy the contained Mojo object at a moments notice whenever the objects reference count goes to 0. MODULAR_ORIG_COMMIT_REV_ID: 634ff657d7b4e07e0e8bc1f9396e7d13af912f08 - [SERVOPT] Zero-initialize KVCache buffer Uninitialized KVCache buffers can result in NaNs in model output. Zero initializing the memory mitigates this, and adds negligible latency overhead. This allows us to be a lot more aggressive about taill call optimization in the presence of stack temporaries.
