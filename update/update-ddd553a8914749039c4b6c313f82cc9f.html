- fix(asr): end-align the final window at the last speech-bearing frame (#747) (#800) Closes #747. ## Problem On quiet long-form audio the transcript ends several words early with high confidence and no error. Validated against the reporter's reproducer (17.28 s, 16 kHz mono, peak ≈ 1.7% FS — genuinely quiet). Stock `main` drops the final clause: > "…phases without me." ❌ (missing: "as long as your confidence is reasonable.") Root cause: the **final** sliding window is a short chunk zero-padded up to the model window, so the encoder sees a frame distribution dominated by digital silence. On speech that is already near the noise floor, that degenerate input pushes every emission to blank. The seam-gap repair (#761) only walks gaps *between* tokens, so a tail dropped past the last emitted token was never examined. ## Fix **1. End-align the final window (structural).** A short final chunk fills its window backwards with real audio instead of zeros (`ChunkProcessor.lastChunkWarmupSamples`). The backfilled prefix rides the existing warmup mechanics — decoded from frame 0, tokens before the original chunk-start frame suppressed via `emitTokensAfterGlobalFrame` — so emitted coverage and the merge overlap with the previous chunk are unchanged. The model simply never sees a mostly-zeros window, and the final chunk gains real left acoustic context. The window ends at the **last speech-bearing frame** (`speechEndSamples()`), not EOF: recordings often end in operator silence or digital zeros, and a window ending inside a dead-silence run *within its declared audio length* decodes degenerately even when the silence is recorded (measured on an Earnings-22 call: 12 s of speech decodes perfectly alone, loses its first half with 1 s of the recording's silent tail appended, decodes to **empty** with all 3 s — while zero padding beyond `audio_length` is masked and harmless). The trim threshold is `speechRmsFloor` — below any real speech — so nothing transcribable is excluded; an all-sub-floor tail is skipped outright. No repair pass, no probe, no splice: an earlier iteration of this PR shipped a trailing-drop repair pass (probe + tail re-decode + splice + stale-punctuation trim); the structural fix makes the disease impossible instead of treating the symptom, and deletes all of it. Prefix suppression is a V3-decoder feature: the tdtJa dispatch now forwards it (`TdtDecoderV3` underneath); v2/tdtCtc110m keep the zero-padded layout (`supportsSuppressedPrefix`) since `TdtDecoderV2` would emit the prefix twice. Applies to both the default loop and the dual-decode arbitration path. Files shorter than one window are unaffected (whole-file decode; padding there is unavoidable and harmless). **2. Adaptive speech gate for the seam-gap repair.** The reproducer exposed a dead gate in the shipped seam-gap pass (#758/#761): its speech-energy probe used an absolute per-frame RMS threshold (0.008), but quiet recordings sit far below it — the gate could never fire on the audio class it guarded. Replaced with a threshold adapted to the recording's own level: ``` min(0.008, max(0.0005, p75FrameRms × 0.3)) ``` Normal-level audio clamps to the previous 0.008 ceiling (existing behavior preserved); quiet recordings scale down with an absolute floor so dither never counts as speech. Frames of exact digital silence are excluded from the percentile (they are *no recording* and would collapse the gate to its floor on silence-heavy files). Constants are named (`speechRms*`) with a full value-rationale table in `LongTranscription.md`. ## Result Fix branch output matches the reporter's expected transcript exactly: > "Please do keep going autonomously. I won't be around much, so feel free to continue working through multiple steps or phases without me as long as your confidence is reasonable." ✅ ## Verification - Reproducer: byte-exact match with expected transcript (default `ASRConfig`, batch `transcribe`) - 20-file LibriSpeech test-clean identical to stock `main` (0.7% avg WER, 0.2% avg CER) — all single-chunk, so additionally: - **A/B vs stock `main` on 7 long multi-chunk files** — 4 hour-long Earnings-22 calls (WER-scored against references) + 3 long MUSAN recordings (7–10 min): **byte-identical on 5 of 7**; the only diffs are two ground-truth-verified tail improvements — "this connect" → "disconnect" (reference: "YOU MAY NOW DISCONNECT") and filler smoothing ("uh"/"Um and" → "And") on spontaneous speech. A custom-vocabulary test likewise produced byte-identical output while improving from 2.50 s to 1.75 s. - OfflineDiarizerManager: split process() into prepare()/cluster() for cacheable segmentation+embeddings (#789) ### Why is this change needed? `OfflineDiarizerManager.process()` bundles segmentation → embedding extraction → clustering into one monolithic call. Segmentation and embedding extraction are **deterministic** and dominate the runtime (CoreML inference over the whole audio), while clustering (AHC + VBx) is the only stage whose outcome callers may want to vary or re-run — e.g. multi-run candidate selection with exact speaker-count constraints, or refiners sweeping clustering thresholds. Today such consumers must repeat the identical inference stages 2–3× just to vary clustering. ### What this PR does Splits `process()` into two composable phases, with the existing API preserved: - **`prepare(audio:)` / `prepare(audioSource:audioLoadingSeconds:)`** — runs segmentation + embedding extraction (concurrent, internals unchanged) and returns a cacheable `PreparedDiarization` handle. - **`cluster(_:)`** — runs AHC + VBx clustering, centroid assignment, reconstruction, and the configured post-passes (zero-vote re-embed, short-segment relabel) over a prepared handle. Callable any number of times per `prepare`. - **`process()` is now exactly `prepare()` + `cluster()`** — behavior, stage ordering, error surface, and `PipelineTimings` semantics are preserved. `PreparedDiarization` is an opaque `Sendable` value type: its stored fields are internal implementation types, it retains the `AudioSampleSource` (clustering post-passes re-embed exact audio spans), and it exposes only `embeddingCount` / `segmentationChunkCount`. ```swift let prepared = try await manager.prepare(audio: samples) let runA = try manager.cluster(prepared) let runB = try manager.cluster(prepared) // no re-segmentation, no re-embedding ``` No changes to segmentation, embedding, or clustering internals. ### Measurements Same audio, same config, real models: | Scenario | Wall time | |---|---| | Baseline: `process()` × 2 | 1.314 s | | Two-phase: `prepare()` once (0.588 s) + `cluster()` × 2 (~7–8 ms each) | 0.602 s (**54% saved**) | | At runCount = 3 | **69% saved** | All output fingerprints are bit-identical between `process()` and the equivalent `prepare()`+`cluster()` sequence, and across repeated `cluster()` calls on the same prepared handle. ### Testing - `swift build` clean on current `main`. - Full test suite green on current `main` (`swift test --parallel`). - `swift format lint` clean on the changed files. - Showcase: add Better Voice (#798) Adding **Better Voice** to the Showcase section, appended at the end to keep chronological order.
