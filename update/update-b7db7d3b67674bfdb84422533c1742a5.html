Суммаризация (на русском)

Colima теперь корректно определяет каталог конфигурации, когда переменная `XDG_CONFIG_HOME` не задана, предотвращая создание дублирующего `~/.colima` при наличии `~/.config/colima`. Ранее в таких средах (например, `brew services`) colima отдавала предпочтение устаревшему каталогу `~/.colima`. Обновление гарантирует, что `~/.config/colima` будет использоваться, если он существует, в соответствии со спецификацией XDG. Существующие каталоги `~/.colima` и новые установки на macOS по-прежнему по умолчанию используют `~/.colima`.

Исходный текст

- core: fall back to the XDG default config dir when the variable is unset (#1603) Processes started without a shell environment resolve the config dir with XDG_CONFIG_HOME unset - launchd via `brew services` being the common case. When the user config lives in ~/.config/colima, such a start created and adopted a second config dir at ~/.colima, and every subsequent run then preferred the legacy dir over the XDG one. Treat an unset or empty XDG_CONFIG_HOME as ~/.config per the XDG Base Directory spec, and adopt an existing ~/.config/colima before falling back to creating the legacy macOS directory. Precedence is otherwise unchanged: an existing ~/.colima still wins, and fresh installs on macOS still default to ~/.colima.
