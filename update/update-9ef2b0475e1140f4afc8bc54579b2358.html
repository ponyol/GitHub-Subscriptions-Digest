Estimate image context tokens from resolution, not byte size (#1511) * Estimate image context tokens from resolution, not byte size Dragging a multi-MB image into chat instantly spiked the context estimate to hundreds of thousands / millions of tokens and disabled Send, while a small screenshot of the same content worked. Root cause: Attachment.estimatedTokens derived IMAGE tokens from base64 byte length (bytes * 4/3 / charsPerToken). Vision tokens scale with resolution, not file bytes — the processor resizes then patchifies, so JPEG compression ratio is irrelevant. A high-res photo whose decoded bitmap is ~33 MB read as ~11,000,000 tokens (matching the ~10990k/262k report) and tripped the hard send-budget gate. Estimate from pixel dimensions instead: read the image header via ImageIO (no full decode), resize the long side into a representative processor budget (1536 px), count merged patches (14 px ViT patch x 2x2 merge = 28 px stride), floor at 256 (Gemma 3 fixed-tile) and cap at 4096 so a single image can never falsely trip the gate. Spilled imageRef (dimensions unavailable) falls back to a 1024 constant rather than the byte figure. Model-agnostic by design — exact counts vary by VL family (Gemma 3 256/img, Qwen2.5-VL dynamic) and the real count is still processor-determined at decode; this only needs a sane budget bound.
