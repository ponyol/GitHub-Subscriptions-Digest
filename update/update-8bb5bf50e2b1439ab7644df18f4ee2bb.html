Это обновление добавляет всестороннюю поддержку хост-ядра версии 6.18, интегрируя её в процессы тестирования, документации и CI. Ключевые обновления зависимостей включают инструментарий Rust до версии 1.96.0 и многочисленные зависимости группы Firecracker, а также обновления Python для образа devctr. Кроме того, усилена безопасность за счет ограничения выделения исполняемой памяти (флаги PROT_EXEC для mmap/mprotect), а тесты производительности в CI оптимизированы для поддержки нового ядра.

Signed-off-by: Jack Thomson <jackabt@amazon.com> - test: exclude IA32_DEBUGCTL from cpu-template-helper MSR check test_cpu_config_dump_vs_actual compares the cpu-template-helper dump (Firecracker's initial CPU config) against the MSRs read from a running guest. On 6.18 hosts, KVM virtualizes bus lock detection, so the guest kernel enables it at boot and sets DEBUGCTLMSR_BUS_LOCK_DETECT (bit 2) in MSR_IA32_DEBUGCTL (0x1d9). The dumped value is still 0, so the actual guest value (0b100) no longer matches. IA32_DEBUGCTL is a R/W MSR modified by the guest OS at runtime, so add it to MSR_EXCEPTION_LIST alongside the other guest-modified R/W MSRs (e.g. MSR_IA32_SPEC_CTRL, MSR_IA32_FEAT_CTL). Signed-off-by: Jack Thomson <jackabt@amazon.com> - test: fix host-vs-guest CPU feature expectations on 6.18 hosts Running test_host_vs_guest_cpu_features on a 6.18 host surfaced a few stale expectations that were not covered when the 6.18 sets were added: - All x86 models (Intel Ice Lake, Intel Sapphire/Granite Rapids, AMD Milan and AMD Genoa): v6.6+ drops the "invpcid_single" synthetic flag, so a 6.18 host (>= 6.6) no longer reports it while our < 6.6 guests still synthesize it. Expect it as a guest-only feature in that case [1]. - AMD Genoa: KVM advertises AMD PerfMonV2 to guests since v6.5, so a 6.18 host passes "perfmon_v2" through. The guest only reports it if its kernel knows the flag (added in v5.19), so drop it from the host-only set for guests >= 5.19 and keep it for older guests (e.g. 5.10) [2]. - Intel Sapphire/Granite Rapids: KVM now advertises IBT to the guest, so "ibt" is no longer host-only for guests new enough to know the flag (added in v5.18). Additionally, the 6.18 Granite Rapids host enables split lock detection, which is host-only since the guest cannot read MSR 0x33.
