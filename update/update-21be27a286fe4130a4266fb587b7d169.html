MODULAR_ORIG_COMMIT_REV_ID: e6c9888327a0e2b58a88bfb6d4f1620f8f9c6f97 - [Kernels] Optimize MLA split-K reducer on MI355 The MLA split-K reduce kernel was taking ~37% of decode GPU time despite doing trivial work. Four reducer-side changes cut its per-dispatch time roughly in half and improve end-to-end MLA decode by 4-22% across the num_heads in {16, 64, 128} sweep with no regressions. First, the per-iteration `if p < num_partitions` predicate in step 2 forced each `global_load` into its own basic block, blocking the compiler from software-pipelining HBM loads across iterations. Replacing it with an index clamp (`min(p, num_partitions - 1)`) keeps the load in-bounds and relies on the existing `scale > 0` mask (scales for slots `>= num_partitions` are already 0 because step 1 leaves their lse at -inf) to zero out the clamped contributions. Step 1 gets the same treatment with a ternary that masks the clamped value to -inf. Second, the step-2 `comptime for` is split into a load phase that writes per-iteration slots in an `InlineArray`, followed by an FMA phase. With the predicate gone the compiler issues all `parts_per_warp` loads up front with a single `vmcnt` drain. Third, a warp-level bail at the start of step 2 (`if part_start_warp < num_partitions`) lets fully-OOB warps skip the load-decouple loop entirely and jump to the step-3 barrier. This matches the old predicated kernel's behavior for fully-OOB warps and is critical for large-grid / small-np shapes (e.g. num_heads=128 bs=8 → np=16, only 2 of 16 warps in a CTA have real work). Fourth, defaults are retuned: target `parts_per_warp = MAX_PARTITIONS / W = 8` (the HBM-latency / FMA-throughput sweet spot for software pipelining). 64-kernel uses W=8, 128-kernel uses W=16. `D_TILES` defaults to 8 for `num_heads <= 16` (tiny grids need extra CTAs to spread work) and 4 otherwise.
