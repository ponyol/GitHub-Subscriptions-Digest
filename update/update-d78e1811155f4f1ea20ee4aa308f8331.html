Первое обновление добавляет руководство для пользователей `drf-spectacular`, объясняющее, как устранить ошибку валидации генератора клиента, связанную с наследованием тела запроса `@action`, и предлагающее явные решения. Второе обновление вводит ограничение частоты попыток перебора токенов для аутентификации в `django-grpc`, повышая безопасность от атак методом подбора на токены сессий, что не покрывалось существующими ограничениями на подбор паролей.

Исходный текст

- docs(django-cfg): add guide for @action request body validation The client generator runs a strict validation pass over the OpenAPI IR before emitting code. One of those rules - `action_inherited_viewset_body` - blocks generation when a DRF `@action` detail endpoint silently inherits its ViewSet's default request body from `drf-spectacular`. This change adds a new guide page that explains the error, why it is a hard failure rather than a warning, and the three accepted ways to fix it: 1. Declare `@extend_schema(request=None)` if the action takes no body 2. Use `inline_serializer(...)` to define a custom request body 3. Explicitly set `request_body=None` on the `@action` decorator - feat(django-grpc): add token probe rate limiting Introduce token probe rate limiting to the django-grpc authentication flow. This adds: - `record_token_probe_failure()` to track failed token probes per session - `reset_token_probe_failures()` to clear the probe counter on successful verification - `is_token_probing_locked()` to check if a session is rate-limited - Constants `PROBE_FAILS_LIMIT` and `PROBE_FAILS_WINDOW_SECONDS` to configure the rate limit This helps mitigate the risk of attackers brute-forcing session tokens, which was not covered by the existing password rate limiting. The token space is much larger than the password space, making brute-force attacks more feasible.
