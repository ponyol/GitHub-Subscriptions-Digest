Суммаризация (на русском)

Обновление в первую очередь исправляет проблему, при которой API баз данных продуктов возвращали общую ошибку 500 вместо конкретной 404 для идентификаторов баз данных неверного типа, за счет централизации проверки типов. Оно также вводит пакетное выполнение операций upsert и добавляет телеметрию для операций с почтой и сообщениями. Среди ключевых внутренних улучшений — отказ от Swoole PDOProxy в пользу прямого взаимодействия с базой данных и уточнение схем безопасности для имперсонации. Кроме того, усилена проверка владения установками VCS для предотвращения проблем между проектами.

Centralise the per-path "allowed database types" in one source (Action::getAllowedDatabaseTypes), used by BOTH the list filter (getDatabaseTypeQueryFilters) and the by-id guard (isDatabaseTypeMismatch), so the two cannot diverge. TablesDB keeps legacy compatibility (mirrors listTablesDatabases); documentsdb/vectorsdb are scoped to their own type; the legacy /v1/databases API is not type-guarded. Every database carries a non-null type (set on create, backfilled to 'legacy' by migration V23), so the filter is a plain Query::equal and the redundant TablesDB list-filter override is removed. Apply the guard at every database-resolution site in the module, and make the remaining handlers type-aware so they can use it: re-base Databases Get/Update/Delete and the Databases/TablesDB log lists onto the type-aware base, and re-base the Collections Attributes/Indexes Action bases and Usage/Get onto it as well (with covariant setHttpPath signatures).
