Это обновление представляет две ключевые функции: настройку базового URL для клиентов Mistral SDK и поддержку высокодоступных топологий Redis Sentinel. Параметр `MISTRAL_BASE_URL` позволяет переопределить конечную точку API Mistral по умолчанию, что полезно для собственных развертываний или работы через прокси. Для Redis новые настройки `REDIS_NODES` и `REDIS_SERVICE_NAME` обеспечивают подключение к кластерам, управляемым Sentinel, поддерживая автоматическое обнаружение мастера и переключение при сбое для клиентов и pubsub-адаптера.

- feat(mistral): make Mistral SDK base URL configurable (#1803) Add a single optional `MISTRAL_BASE_URL` setting that overrides the `server_url` passed to every `Mistral(...)` SDK client constructed in the backend: the dense embedder, the OCR client, and the chat LLM adapter. When `MISTRAL_BASE_URL` is unset, every adapter explicitly falls back to `MISTRAL_DEFAULT_BASE_URL` (`https://api.mistral.ai`), a module-level constant in `airweave.core.config.settings`. This keeps the production endpoint visible in the source rather than relying on the SDK's internal default, and gives us a single seam to layer per-adapter version overrides on later if needed. Behavior is unchanged for existing deployments — the explicit default matches what the SDK was using implicitly. Setting `MISTRAL_BASE_URL` routes every Mistral client to the override URL, which is useful for hitting a self-hosted Mistral deployment or a corporate proxy. Also expose the new setting in `.env.example` and update the `_create_dense_embedder` factory and the `MistralDenseEmbedder` ctor to forward the value. Co-authored-by: Mistral Vibe <vibe@mistral.ai> - feat(redis): support Sentinel for high-availability Redis topologies (#1796) * feat(redis): support Sentinel for high-availability Redis topologies The Redis client and pubsub adapter previously only accepted a single host/port pair. In HA deployments using Redis Sentinel (e.g. Bitnami's chart with `architecture=replication`), there is no stable master service to point `REDIS_HOST` at — the master can move between nodes on failover and clients must discover it via Sentinel. This change adds an opt-in Sentinel mode via two new settings: REDIS_NODES JSON list of [host, port] sentinel nodes, e.g. '[["redis-node-0", 26379], ["redis-node-1", 26379]]' REDIS_SERVICE_NAME the master name registered with Sentinel (e.g. "mymaster") When both are set, the new `redis_factory.make_redis_client(...)` uses `redis.asyncio.sentinel.Sentinel(...).master_for(...)` to discover the current master and transparently reconnects after a failover. Otherwise, behaviour is identical to before (single `REDIS_HOST`/`REDIS_PORT` pool). The pubsub adapter is also routed through the same factory, replacing the hand-rolled `redis.from_url(...)` path that could not express a Sentinel connection.
