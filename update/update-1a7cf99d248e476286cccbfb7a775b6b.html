Этот релиз значительно повышает надежность и безопасность Faiss за счет добавления обширной проверки входных данных, контроля границ и предотвращения переполнений, особенно для процессов десериализации в различных компонентах, таких как квантайзеры, индексы и графы, что предотвращает сбои и уязвимости. Также расширена функциональность за счет реализации `distance_to_code` для `IVFRaBitQFastScanScanner` и индексов `IVFPQFastScan`, что позволяет оценивать расстояния для каждого кода. Дополнительные улучшения включают рефакторинг кода для компактности и улучшенное управление памятью с использованием `std::unique_ptr` для безопасности исключений, а также обновление инструкций по установке через conda.

- Implement distance_to_code for IVFRaBitQFastScanScanner (#4822) Summary: Pull Request resolved: https://github.com/facebookresearch/faiss/pull/4822 The IVFRaBitQFastScanScanner previously threw an error for distance_to_code, making it incompatible with use cases that need per-code distance evaluation (e.g., custom inverted list scanning, re-ranking). This implements distance_to_code by delegating to the existing RaBitQDistanceComputer, assuming the caller provides standard-format RaBitQ codes (as produced by encode_vectors), not FastScan-packed codes. This mirrors the approach used by IndexIVFRaBitQ's scanner. The scanner's set_query and set_list methods now also initialize a FlatCodesDistanceComputer with the appropriate centroid, qb, and centered parameters so that distance_to_code can be called after both are set.
