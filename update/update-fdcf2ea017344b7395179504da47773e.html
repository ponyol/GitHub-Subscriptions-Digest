Hdr gains a uintptr_t fwd field (16 bytes, up from 8). Zero during normal execution. The GC writes the new address here when evacuating an object, and sets type = GC_FORWARDED (0xFFFFFFFF). Placing fwd in the header (not in the first payload word) is safe for concurrent GC: a racing mutator can always read type without racing with a payload write. Non-retrofittable — must be in place before any compacting/generational GC is written. 2. gc_ops_t vtable wraps all GC operations: alloc, collect, register_thread, pin/unpin, register_root/unregister_root, heap stats. Boehm sits behind it as the initial backend (gc_boehm_ops). A precise generational collector plugs in by replacing gc_ops before gc_init(). All existing call sites (CURRY_NEW, gc_alloc, gc_collect, ...) are unchanged — they now go through the vtable inline. 3. GcNursery per-thread structure and gc_nursery_alloc fast path. Under Boehm the nursery stays permanently exhausted (top == limit == NULL) so every allocation falls through to gc_ops->alloc — behaviour is identical to before. The slab mechanism becomes live when a precise GC backend is installed: objects in a slab are then individually understood by the collector, and the bump-pointer path becomes real. C/C++ modules: no changes needed. Boehm conservatively scans C stacks; pin/unpin and root registration are no-ops under the Boehm backend.
