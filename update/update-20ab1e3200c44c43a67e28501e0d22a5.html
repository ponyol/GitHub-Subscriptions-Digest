This release introduces significant enhancements, including image classification and clustering, improved document element recognition (headings, image placeholders), and an expanded API surface. Driven by extensive updates to the `alef` binding generation tool, new language bindings for Kotlin, Swift, Dart, Gleam, and Zig have been added, alongside numerous fixes and improvements for existing integrations. The release also includes developer experience improvements, such as a local demo environment command, comprehensive end-to-end test repairs, and various CI/CD refinements for build stability and compatibility. --- **Russian translation:** Этот выпуск содержит значительные улучшения, включая классификацию и кластеризацию изображений, улучшенное распознавание элементов документа (заголовки, заполнители изображений) и расширенный API. Благодаря обширным обновлениям инструмента `alef` для генерации привязок, добавлены новые языковые привязки для Kotlin, Swift, Dart, Gleam и Zig, а также многочисленные исправления и улучшения для существующих интеграций. Выпуск также включает улучшения для разработчиков, такие как команда для локальной демонстрационной среды, всесторонние исправления сквозных тестов и различные доработки CI/CD для стабильности и совместимости сборки.

Image classification + clustering (#788 follow-up) -------------------------------------------------- Heuristic image-kind classifier and per-page tile clusterer so consumers can tell tile-fragments of one figure apart from standalone photographs/ charts/icons without resorting to count-based guardrails. Public API (additive, no semver break): - ImageKind enum: Photograph, Diagram, Chart, Drawing, TextBlock, Decoration, Logo, Icon, TileFragment, Mask, Unknown - ExtractedImage gains image_kind, kind_confidence, cluster_id - ImageExtractionConfig.classify (default true) toggles the pipeline The classifier is offline, deterministic, and uses already-captured signals: dimensions, aspect ratio, colorspace, bits-per-component, format, plus Shannon entropy of a 64x64 thumbnail. The cluster pass groups same-page images with similar dimensions whose bounding boxes sit within half a tile-side of each other, so a technical drawing composed of N raster fragments surfaces as one cluster_id with all members reclassified to TileFragment. Wired through every extractor that produces ExtractedImage: PDF (lopdf and pdfium fallback), DOCX, PPTX, HTML, ODT, EPUB, FictionBook, Jupyter, RTF, and the standalone image extractor. classify and cluster_tiles excluded from the binding surface as internal helpers. Log hygiene (#787) ------------------ Default subscriber now layers ureq=warn, ureq_proto=warn, rustls=warn, hyper_util=warn, hf_hub=info, tower_http=info on top of any user-supplied RUST_LOG. Per-target rules in RUST_LOG continue to win, so explicit RUST_LOG=ureq=debug still surfaces full transport detail when needed. API router's TraceLayer demotes per-request/response events to DEBUG and keeps failures at WARN, so the default `info` level produces zero per-request log lines instead of one DEBUG line per HTTP turn. Investigation found no per-element info! call sites; existing logging volume comes entirely from third-party transport crates plus the one-time hf-hub model-fetch chatter. The model itself is cached on disk under HF_HOME and in-process via LazyLock engine cache, so the chattiness was not a re-fetch bug.
