Это обновление вводит значительные улучшения, наиболее заметными из которых являются деклараторы таблиц на основе классов (в стиле dataclass) через `TableModel` и `ViewModel`. Эти новые модели упрощают объявление таблиц и представлений, позволяя напрямую вызывать методы таблиц и обеспечивая типовую безопасность благодаря автоматически генерируемым заглушкам. Кроме того, выпуск включает улучшенную информацию о типах для видео UDF, реорганизацию модуля `video.py`, расширенную обработку литералов перечислений и удаление внешней зависимости от LabelStudio.

- Remove external stores/LabelStudio (#1436) - PXT-1228: typing info for video udfs that return pxt.Json (#1435) Also: finally reorganizes video.py into a separate submodule - Expand handling of enum literals (#1438) - Class-based table declarators (#1434) Introduces class-based ("dataclass-style") Table declarators via a new `TableModelMetaclass`. The metaclass has two instances, `TableModel` and `ViewModel`, that are used to declare tables and views, respectively. A model gets resolved to a `Table` instance when any action is taken on it, and most of the functionality on `TableModel` is a pass-through to that underlying `Table`. Columns are added promptly to the model namespace at declaration time, and can be referenced in the usual way for subsequent computed columns. Table methods (`select()`, `collect()`, `where()`, etc.) can be invoked directly on `TableModel`. In order to avoid having to maintain 20+ method signatures in parallel, a mechanism is introduced where (i) selected table methods are passed through to the underlying `Table` class via `TableModelMetaclass.getattr()`; and (ii) a `model.pyi` file is auto-generated via a new `generate_type_stubs.py` tool, based on the signatures in `pxt.Table`, ensuring that the signatures are both auto-synced and are cognizable to static type checkers. Major TODOs: - Extend the validation logic of the model against existing tables - Auto-merge of schemas in response to model changes - Embedding index creation is currently a separate DB transaction; it should be brought under the transaction umbrella of table creation
