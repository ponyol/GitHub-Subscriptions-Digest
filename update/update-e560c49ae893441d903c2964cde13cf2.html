Суммаризация (на русском)

Это обновление содержит несколько исправлений ошибок и улучшений отображения для Org Social. Основные изменения включают устранение ошибки "Emojify not available" путем правильной загрузки пакета, фильтрацию бессмысленных цепочек бустов из лент и точное отображение ответов с настроением и текстом. Значительное исправление гарантирует, что фильтр по дате корректно поддерживает форматы идентификаторов Org Social v1.6, предотвращая исключение недавних постов из пользовательских лент.

Исходный текст

- Merge branch 'develop' - Fix emojify availability check by loading package before verification The function org-social-ui--add-reaction was showing "Emojify not available" even when the package was installed. This happened because the code checked if emojify-completing-read existed before attempting to load the emojify package. Added (require 'emojify nil t) before the fboundp check to ensure the package is loaded, making the function available when the package is installed. - Added FAQ - Merge branch 'develop' - Filter invalid boosts from timeline Boosts without text that point to empty posts (boost chains without content) are now automatically filtered out from timeline and other buffers. This prevents displaying meaningless boost chains where users boost empty boosts. - Merge branch 'develop' - Fix timeline filter to show replies with mood and text Replies with REPLY_TO + MOOD + text were incorrectly filtered as reactions. Now only filters posts with REPLY_TO + MOOD but without text (true reactions). - Merge develop into main: Fix v1.6 ID format support in date filter - Fix date filter to support Org Social v1.6 ID format The date filter in org-social-feed--filter-by-date was only extracting post IDs from properties (:ID:), causing posts with v1.6 format IDs (in the header) to be incorrectly excluded from the timeline. This fix adds support for both formats: - v1.6 format: ID in post header (** TIMESTAMP) - Legacy format: ID in properties (:ID: TIMESTAMP) The header ID takes priority when both are present, matching the behavior of org-social-parser--get-posts-from-feed. This resolves the issue where recent posts (like the 2026-01-14 post about reaching 50 feeds) were not appearing in users' timelines.
