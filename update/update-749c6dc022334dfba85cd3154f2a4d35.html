Суммаризация (на русском)

This release significantly enhances security and access control, notably by fortifying IP pinning to prevent bypasses, correctly propagating resource access IDs in app sessions, and introducing a new `DelegationSession` resource for granular access delegation. Further improvements include expanded support for Browser MFA, mTLS certificate-based authentication for the Access Graph API, and advancements in cloud resource discovery and `WorkloadIdentity` management. The update also addresses various bug fixes, integrates dependency updates, and improves documentation with new user guides and architectural overviews. --- **Russian translation:** Этот выпуск значительно повышает безопасность и контроль доступа, в частности, за счет укрепления привязки IP-адресов для предотвращения обхода, корректной передачи идентификаторов доступа к ресурсам в сессиях приложений и введения нового ресурса `DelegationSession` для детального делегирования доступа. Дальнейшие улучшения включают расширенную поддержку Browser MFA, аутентификацию на основе mTLS-сертификатов для Access Graph API, а также усовершенствования в обнаружении облачных ресурсов и управлении `WorkloadIdentity`. Обновление также содержит различные исправления ошибок, обновления зависимостей и улучшение документации с новыми руководствами пользователя и обзорами архитектуры.

(#65089) - fix: Propagate AllowedResourceAccessIDs into app session certificates (#65115) App sessions created via CreateAppSession and generateUserCerts were not carrying AllowedResourceAccessIDs from the caller's identity into the app session certificate. This meant that checkAllowedResources() at the app service was a no-op for every app session, falling back to role-based checks alone. A user with an approved Resource Access Request could create an app session for any application their request's roles permitted, bypassing the resource-level restriction that should limit access to the specific app(s) in the request's AllowedResourceAccessIDs. Pass RequestedResourceIDs through the NewWebSessionRequest in both CreateAppSession (lib/auth/sessions.go) and generateUserCerts (lib/auth/auth_with_roles.go) so that the resulting app session certificate carries AllowedResourceAccessIDs and the app service enforces them. Add AWSRoleARNMatcher to WithConstraints for principal-level narrowing at the app service.
