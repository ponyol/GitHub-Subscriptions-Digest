- Merge pull request #1183 from diegobonato/fix/handle-oserror-in-project-path-validation Handle OSError when validating registered project paths on startup - Handle OSError when validating registered project paths on startup When a registered project path points to a stale or unreachable filesystem (e.g. a disconnected SSHFS mount), `path.exists()` raises `OSError: [Errno 5] Input/output error` instead of returning False. This uncaught exception crashes the entire MCP server on startup, making all Serena tools unavailable. Wrap the `path.exists()` call in a try/except OSError so that inaccessible paths are gracefully skipped with a warning, matching the existing behavior for non-existent paths.
