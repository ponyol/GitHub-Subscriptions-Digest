Суммаризация (на русском)

Это обновление объявляет устаревшими модели `deepseek-reasoner` и `deepseek-chat`, предлагая `deepseek-v4-flash` в качестве замены, и вводит методы `TableModel.diff_all()` и `TableModel.update_all()` для синхронизации каталога, а также поддержку изменения необнуляемых столбцов на обнуляемые. Были значительно улучшены стабильность и производительность системы за счет повышения потокобезопасности, переработки кеширования версий таблиц, исправлений в обработке транзакций PostgreSQL и сегментации SAM3. Релиз также запрещает "анонимные" составные выражения в моделях представлений, включает различные улучшения CI/тестирования и исправления для миграции базы данных.

Avoid inserting XML documents to `base_table` because document splitter does not yet support XML (https://pixeltable.atlassian.net/browse/PXT-1249), and doing so causes an `AssertionError`. The nature of `test_db_migration` failing on some platforms but not others may have to do with the order in which `glob.glob` returns matching files. - [PXT-1236] get rid of caching in TableVersionHandle (#1464) Motivation: to fix [PXT-1236](https://pixeltable.atlassian.net/browse/PXT-1236), we want to start evicting older (LRU) cached TV entries from `Catalog._tbl_versions`. The thread-local cache in `TableVersionHandle` gets in the way of that: if a table is evicted from Catalog's cache but is still in `TableVersionHandle._local`, we can end up mixing two different `sql.Table` instances in a query, which results in errors. Besides, a thread-local cache in `TableVersionHandle` is confusing and difficult to reason about. Here's why the new code is semantically and performance-wise equivalent to the old one. When in transaction, the new code simply relies on Catalog to obtain table version. Catalog maintains its own cache, so the new code has a similar performance (i.e. TV will only be loaded if it isn't already cached and validated). When not in a transaction and effective version is `None` (i.e. live table): the old code would always go down the `cat.get_tbl_version()` path, same as the new code. To understand why the `return cached` branch would never be hit, observe that Catalog resets `is_validated` to `False` on all live tables at the end of each transaction. A live table is never "valid" unless it was validated in the current transaction, but in this case there's no current transaction. When not in a transaction and effective version is not `None` (i.e. snapshot): if there is a cached instance, both the old and the new code return it without starting a new transaction. If not, in both cases a transaction is started to load the snapshot, which is then cached. Also in this pr: `Catalog.get_tbl_version()` and `Catalog._get_tbl_version`: `validate_initialized` param defaults to True.
