- fix(ui): toggleFavorite last-click-wins + filter re-render Two follow-up fixes surfaced during the codex review of the earlier memora#39 favorite persistence fix: #541 — rapid double-clicks on the favorite star could leave the DB and client cache at the older request's state if two PATCH requests completed out of order. The optimistic-UI-then-revert pattern had no protection against overlap. Add a per-memory sequence counter: each click bumps the counter, and completion handlers (both .then and .catch) early-return if their captured seq is older than the current one. Last click always wins. Every click still fires a request, so the UX stays responsive; only stale responses get dropped. #542 — un-favoriting a memory while the timeline filter was set to Favorites toggled the star and updated the cache correctly, but the DOM row stayed visible because nothing re-applied the filter. After the earlier #39 fix this became more visible (data contradicted the view instead of silently staying in a broken-favorited state). Add a renderTimelineList call inside the success handler, guarded by timelineFilter === 'favorites', so the list stays consistent with its current filter after any favorite toggle.
