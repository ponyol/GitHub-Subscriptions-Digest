Суммаризация (на русском)

Основное обновление касается тайм-аута выполнения кода в песочнице, который был сначала увеличен до 60 секунд из-за проблем с производительностью у медленных поставщиков LLM, а затем стал настраиваемым (по умолчанию 30 секунд), что позволяет операторам регулировать его. Среди других значительных изменений — внедрение механизма подтверждения "человек в контуре" (Human-in-the-Loop, HITL) для простого исполнителя и настраиваемый тайм-аут HTTP-запросов к LLM. Обновление также включает исправления различных ошибок, таких как обеспечение распространения параметров аутентификации и корректировка трассировки Langfuse, а также важные меры по устранению уязвимостей безопасности в зависимостях.

- refactor(executors): make sandbox code-execution timeout configurable (default 30s) (#365) * perf(executors): bump sandbox code-execution timeout from 30s to 60s The 30s cap on asyncio.wait_for(_async_main(), timeout=...) was tight for slower model providers. Analysis of a GPT-OSS-120B AppWorld run (non-Groq provider) showed 21 sandbox TimeoutErrors across 15 of 43 tasks (35%), with 6 of those 15 failing — meaningfully above the overall 28% failure rate. The sandbox block wall-clock includes embedded LLM calls (find_tools shortlister, MCP/skill tools that internally call an LLM) and a chain of sequential API requests. On Groq the same workload fits well under 30s; on GPU-based providers (vLLM/TGI/standard inference) it routinely hits the cap. Bump the budget so the model has room to complete typical pagination + find_tools + a few API calls in one block on slower providers, while still bounding runaway loops. - base_executor.py / local_executor.py: timeout default 30 -> 60 - code_executor.py: both explicit callers (cuga_lite path and CodeAgent path) pass timeout=60 instead of 30 - e2b_executor.py / e2b_sandbox.py: generated-code template timeout=30 -> 60 - test_e2b_direct.py: example template literal aligned to 60 OpenSandbox already runs with opensandbox_timeout_seconds=600 and is unchanged.
