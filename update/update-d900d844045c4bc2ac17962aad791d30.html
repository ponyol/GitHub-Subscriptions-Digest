However, the nested dict deletion (`del status[pipeline_name][dataset_id]`) was not detected by SQLAlchemy's `MutableDict` change tracking, which only monitors top-level dict operations. The cleanup ran in memory but was never persisted to the database on commit. - Since dataset IDs are deterministic (`uuid5` of name + user_id + tenant_id), recreating a dataset with the same name produces the **same ID**. Without persisted cleanup, re-added data was incorrectly skipped by the incremental loading cache, which still saw the old "completed" pipeline_status entry. - Fix: use `flag_modified(data_record, "pipeline_status")` from `sqlalchemy.orm.attributes` to explicitly mark the column as dirty after nested dict modifications. ## Root Cause `Data.pipeline_status` is a `MutableDict.as_mutable(JSON)` column. `MutableDict` tracks top-level dict operations (`__setitem__`, `__delitem__`, `setdefault`, etc.) but **not** modifications to nested dicts.
