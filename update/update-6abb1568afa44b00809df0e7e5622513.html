Суммаризация (на русском)

Недавние обновления включают повторное добавление `grpcio-tools` в зависимости пакета. Зависимость от `grpcio` была ослаблена: для генерации заглушек теперь используется старая версия, обеспечивающая совместимость с более новыми релизами `grpcio`, а пользователям предоставлена большая гибкость в выборе версии. Также, все алгоритмы были переписаны в нерекурсивном стиле, чтобы избежать ограничения на глубину рекурсии в Python, при этом функциональность осталась прежней.

Исходный текст

- Add grpcio-tools to package dependencies (#522) I though this is not needed, adding it back. Didn't break CI because CI doesn't install from pypi. - Relax grpcio dependencies (#520) Use old grpcio package version during development when we generate .py grpc stubs. This ensures that the .py proto stub files work with any newer version of grpcio package (same major version). See details about backward compatibility of grpc runtime components with generated code at https://protobuf.dev/support/cross-version-runtime-guarantee/. The old grpcio-tool version we're using is 1.60.0 from Dec 7, 2023. See https://pypi.org/project/grpcio/1.60.0/. Should be safe to use as the oldest supported. Relax version requirements for non-development (real) grpcio package version in pyproject.toml. This version is used by pip install. This allows users to use grpcio version they want (within the same major version). - Rewrite all algorithms in non-recursive way (#518) This is because Python has default recursion limit of 1000 which is pretty easy to break with i.e. a reduce operation of 1000 items list. There are no functioncal changes. The semantic of all operations is the same.
