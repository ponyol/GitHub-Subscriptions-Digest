Это обновление устраняет две ключевые проблемы. Во-первых, исправлена ошибка в `_validate` при обновлении навыков, которая ошибочно сообщала "Траектории с ошибками не найдены" из-за несоответствия при сборе данных; теперь она устранена путем выравнивания поэтапных выводов/оценок с входными данными для каждой траектории с использованием уникальных идентификаторов траекторий. Во-вторых, выходная схема агрегатора банка навыков SFT была приведена в соответствие со схемой `skill_generation` среды выполнения RL, что позволяет использовать унифицированный формат JSON для обеих систем и стандартизирует имена ключей и структуры категорий для разных сред.

- Fix _validate skill-update collecting no failed trajectories (#57) `_validate` collected three parallel lists for the skill-update path: sample_inputs was per-trajectory (taken from the pre-rollout input_ids), while sample_outputs and sample_scores were per-step-entry (one row per active step in test_output_gen_batch). When zipped in _collect_failed_trajectories, the iteration was truncated to the shorter list (= trajectory count N), so only the first N step entries were inspected. Because gather_rollout_data groups step entries by trajectory, if the first few trajectories happened to be successful their step entries filled all N positions, and the `score <= 0` filter returned empty — printing "No failed trajectories found" even when the validation success_rate showed clear failures (e.g. the issue's pick_two_obj_and_place_success_rate=0.286). The fix collects per-step traj_uids alongside sample_outputs / sample_scores during validation, and dedupes outputs/scores by first-occurrence of traj_uid before invoking the skill update — so they align 1:1 with the per-trajectory sample_inputs. Co-Authored-By: Claude Opus 4.7 (1M context) <noreply@anthropic.com> - Align SFT skill bank schema with skill_generation/ The SFT aggregator's output schema (general_principles / category_skills / mistakes_to_avoid) had drifted from skill_generation/{alfworld,webshop, search}.py's schema (general_skills / task_specific_skills (or query_type_skills for search) / common_mistakes), so the same JSON could not feed both the RL runtime (SkillsOnlyMemory) and the SFT distillation pipeline. This rewrites the SFT side to emit the RL-compatible schema: - Top-level keys, skill/mistake field names, and category keys all match skill_generation/ for each env. - ALFWorld categories collapse to the 6 RL keys; WebShop expands to the full 7-way split; Search expands to the 4 query types. - distill_webshop.py now shares classify_webshop_category with skill_retrieval.py so distillation and the RL runtime use the same category keys. The rendered "Retrieved Relevant Experience" markdown block stays unchanged in shape; it now reads description/how_to_avoid instead of dont/instead.
