Это обновление вносит ряд улучшений и исправлений в модули `gptel`. Оно улучшает интеграцию с Org mode, правильно экранируя вызовы инструментов и их результаты для сохранения структуры документа. Исправлена критическая ошибка в `gptel-request`, связанная с расчетом размера полезной нагрузки: теперь используются байты вместо символов, что предотвращает сбои запросов. Добавлена поддержка модели `gpt-5.2` и обновлены метаданные для `gpt-5.1`; система также соответствует стандартам HTTP, не отправляя данные с GET-запросами.

Исходный текст

- gptel-org: Keep tool args from interfering with org structure When written to an Org buffer in a tool call block, tool call arguments that have newlines can interfere with Org's structure, such as if they start with a heading character on a new line. Fix by escaping both the printed representation of the tool call and the tool result, instead of just the tool result. * gptel.el (gptel--display-tool-results): Escape tool call too, not just tool results. * gptel-org.el (gptel-org--unescape-tool-results): Unescape tool call too, not just tool results. - gptel-transient: Require gptel-context before adding current-kill * gptel-transient.el (gptel--infix-context-add-current-kill): `gptel-context-add-current-kill' is not autoloaded by gptel-context, so require it first. - gptel-request: Check payload size in bytes before sending * gptel-request.el (gptel-curl--get-args): When the prompt data is multibyte, the size of the JSON payload in characters is the wrong measure to compare against `gptel-curl-file-size-threshold', to decide if we want to pass the data to Curl in the command line or using a temporary file. This causes queries to fail when they are of intermediate size (i.e. larger than the threshold in bytes but fewer in characters.) Fix by measuring the payload size in bytes. Bug reported by Ihor Radchenko. - gptel-openai: Add gpt-5.2, update metadata for gpt-5.1 gptel-request.el (gptel--openai-models): Add gpt-5.2 to the list of models. (#1211) gptel-openai.el (gptel--request-data): Update system prompt JSON field used for gpt-5.2. gptel-gh.el (gptel--gh-models): Fix metadata for gpt-5 series models. - gptel: Do not send data with GET request (#1208) gptel.el (gptel--url-retrieve): Don't include request data when making a GET request. This also aligns with RFC9110 which strongly discourages sending content with a GET request. https://www.rfc-editor.org/rfc/rfc9110.html#section-9.3.1-6
