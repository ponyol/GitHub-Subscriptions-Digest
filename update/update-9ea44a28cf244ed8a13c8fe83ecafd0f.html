Суммаризация (на русском)

Это обновление вводит поддержку SLSA Provenance v1 для `kit import`, позволяя генерировать аттестации, детализирующие исходники и дайджесты артефактов, что значительно повышает безопасность цепочки поставок и отслеживаемость. Оно также включает ряд улучшений стабильности и безопасности, таких как фиксация коммитов, проверка путей к файлам, очистка URL-адресов и атомарные файловые операции. Кроме того, релиз рефакторизирует распаковку навыков, защищает от нулевых опций, обновляет зависимости Go и GitHub Actions, а также добавляет аннотацию временной метки создания OCI к манифестам ModelKit.

Исходный текст

- Add --attestation-output flag to kit import for SLSA Provenance v1 Emits a SLSA Provenance v1 predicate to a file or stdout for each successful kit import, ready to feed into `cosign attest --predicate`. Default behavior is unchanged. The predicate pins: - source.uri (hf://[datasets/]repo or git+https://host/repo with userinfo scrubbed) - source.digest.gitCommit (HF: PinCommit via /api/.../revision/{ref}; git: ResolveHead on the local clone) - kitfile.digest.sha256 (the OCI config blob hash) - manifest digest (logged to stderr; cosign derives the in-toto Statement subject from the OCI ref) Other changes: - output.OpenDataSink: temp-file + atomic rename for file targets so a failing importer leaves the original file untouched. For "-" the info writer reroutes to stderr so logs don't corrupt stdout JSON. kit init also uses this helper. - hf.PinCommit pins the import to one immutable commit before listing or downloading, eliminating a TOCTOU window where a branch could move mid-import. - hf.DownloadFiles validates every file path with VerifySubpath before any network/filesystem work to prevent path traversal. - kitfilePathFilter mirrors pack's layer-assignment so HF only downloads files that will actually end up in the ModelKit. Handles catchall layers, ignore patterns (Kitfile/.kitignore), and Windows-style separators in cleaned layer paths. - git.SanitizeURL scrubs userinfo from clone URLs in both logs and provenance. Signed-off-by: Gorkem Ercan <gorkem.ercan@gmail.com> - Guard UnpackModelKit against nil options Callers always pass non-nil *UnpackOptions, but the existing L `opts != nil && opts.UnpackDir != ""` guard implied nil was possible while the rest of the function would dereference it unchecked. Return an explicit error at the API boundary instead. Signed-off-by: Gorkem Ercan <gorkem.ercan@gmail.com> - Split skill unpack into a dedicated function Pulls --as-skill handling out of unpackRecursive, which was threaded with opts.SkillOptions guards across every layer case. unpackSkill now only walks prompt layers, skipping Kitfile write, parent-ref traversal, and remote-dataset handling that don't apply in skill mode.
