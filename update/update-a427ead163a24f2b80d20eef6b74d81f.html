Reviewed end-to-end by claude-B + codex via inter-pane bus. - fix(api): tighten /api/memories issue filter to strict metadata.type - fix(embeddings): stop silent fallback to TF-IDF (#457) plus warn-on-fallback follow-up - fix(graph): multiple fixes for endless spinning after drag / realtime reload (5 commits) - fix(web-ui): Favorites filter fetches full set from server (#544) - feat(ui): Issues tab with inline status/category editing Co-Authored-By: Claude Opus 4.7 (1M context) <noreply@anthropic.com> - fix(server): sanitize Pydantic-generated nullable anyOf in tool schemas Anthropic's tool input_schema validator rejects anyOf/oneOf/allOf combinators — including the property-level `{anyOf:[{type:X},{type:null}]}` that Pydantic v2 emits for `Optional[X]` parameters. Every memora tool with a nullable arg (memory_create, memory_update, memory_get, memory_list, memory_hierarchy, memory_semantic_search, memory_hybrid_search, etc. — 19 of 41 tools) was tripping the validator and causing the entire tools/list response to 400, which in turn made Claude Code disconnect the MCP server. Adds two helpers: _collapse_nullable_anyof — recursive walker that mutates the schema in place. When a node has `anyOf` with exactly one non-null branch, it merges the surviving branch's keys into the node and drops the anyOf. Sibling keys (default, title, description) preserved. _sanitize_tool_schemas — iterates every registered tool's `parameters` dict and applies the walker. Called once before `mcp.run()` so all tools/list responses see the cleaned schema. Runtime safety: Pydantic models are unchanged. The schema is purely the surface FastMCP advertises; argument validation routes through `fn_metadata`/`arg_model`, not the schema dict. Optional[X] params still accept None at call time. Verified via independent two-reviewer audit (claude-B + codex via inter-pane bus): runtime, idempotence, deep nesting, non-nullable unions, and editable install scope all pass. Known limitation (theoretical, no current memora tool hits it): `Optional[Union[A,B]]` produces a 3-branch anyOf with one null branch — after stripping null, two non-null branches remain so the walker's `len(non_null) == 1` condition fails and the schema is left unchanged. When the next regression of this shape lands, switch the helper to emit `{"type": ["A","B","null"]}` instead of picking a single branch.
