Это обновление значительно повышает стабильность и производительность приложений Flet. Оно устраняет сбои, связанные с закрытием модальных окон, благодаря отложенному снятию маршрутов, а также решает проблемы с утечками памяти и зависаниями в веб-приложениях при скрытых вкладках, оптимизируя обработку кадров и активность производителей. Кроме того, выпуск добавляет опцию устаревшей упаковки для Android и исправляет ряд ошибок, включая проблему устаревшего кода при отладке. Среди прочих улучшений — корректное сохранение настроек видеоплеера, улучшенная обработка событий касания вне SearchBar и надежность WebSocket-соединений для встроенных и не корневых веб-приложений.

- Fix modal close crash: defer pop to post-frame, target own route (#6714) AlertDialog, CupertinoAlertDialog, BottomSheet and CupertinoBottomSheet popped their route synchronously during build, throwing setState-called- during-build (black screen) when the same frame opened another route/overlay (e.g. a SnackBar shown right after dismissing a bottom sheet). Each modal now tracks its own ModalRoute and closes it in a post-frame callback via a shared closeModalRoute() helper that pops that specific route (animated when topmost, removeRoute otherwise). View's confirm-pop now pops its own route too, so a modal dismissed in the same tick as a view pop can't dismiss the wrong route (previously the reason AlertDialog kept a synchronous pop). Verified with routing, alert dialog, bottom sheet, banner and snack bar integration tests; adds a bottom-sheet close+SnackBar flow test. - Fix hidden-tab frame flood in RawImage and MatplotlibChart web animations (#6691) (#6704) * Handle hidden-tab frame streaming safely Add visibility-aware lifecycle handling for Flutter image streaming in `RawImageControl` and matplotlib chart canvas states. When hidden, incoming frames are now coalesced or applied offscreen without display uploads, ACKs are sent immediately to keep Python producers unblocked, and replaced images are disposed immediately to prevent memory/callback backlogs. On resume, the latest deferred state is presented once, avoiding engine flood/exceptions from queued frame work. * Fix hidden-tab frame flood in RawImage and MatplotlibChart web animations (#6691) On Flet web the frame producer (Pyodide worker or a remote server over a WebSocket) is never throttled by the browser, while the client's Flutter frame pipeline is suspended whenever the tab is backgrounded. setState then schedules frames that never paint and the post-frame callbacks that dispose replaced ui.Images never fire, so decoded images and pending disposals pile up unbounded in the Dart heap and flush into the engine all at once on resume - flooding it with one uncatchable exception per queued frame. Being a client-side accumulation, it also hit native windows minimized mid-animation. Layer 1 (client-side, fixes the crash on every transport): a shared FrameStreamVisibility mixin in flet core, used by both RawImageControl and flet-charts' MatplotlibChartCanvas. While hidden it stops decoding/uploading and frees replaced images immediately (post-frame disposal never runs while hidden), keeps only cheap offscreen state up to date so incremental matplotlib diffs stay correct, and presents just the latest frame on resume. Layer 2 (parks the producer): page.wait_until_visible() / page.app_visible, driven by on_app_lifecycle_state_change via Page.before_event. RawImage and MatplotlibChartCanvas await it in their send path, so producer loops park while hidden instead of rendering frames a suspended client can only discard. Gated before the ack future is allocated so ack_timeout never fires spuriously. * Fix unresolved reST xref in Page.app_visible docstring The website docs check flags any built page whose HTML still contains a literal :attr: directive (an unresolved cross-reference). The reST resolver doesn't run over property/method docstrings the way it does over dataclass field docstrings, so :attr:`on_app_lifecycle_state_change` / :attr:`visible` in the new app_visible property leaked through. Use plain backticks instead. * Fix flet build spinner flooding non-TTY logs (force_terminal auto-detect) The CLI Console was created with force_terminal=True whenever FLET_CLI_NO_RICH_OUTPUT was unset, forcing the rich Live spinner to repaint even into a pipe — flooding CI/cloud-build logs with one line per animation frame. --no-rich-output couldn't fix it (parsed after the module-level console is built). Auto-detect the terminal instead (force_terminal=None): TTYs keep the spinner, pipes stay quiet; FLET_CLI_NO_RICH_OUTPUT still forces plain output. CHANGELOG 0.86.2. * Make --no-rich-output actually produce plain output The flag is parsed per-command, after the module-level rich Console is built, so it never reached force_terminal — only emojis were suppressed while color + the Live spinner kept going. Detect --no-rich-output from sys.argv at import (alongside FLET_CLI_NO_RICH_OUTPUT) so the console is constructed plain (force_terminal=False -> is_terminal False, color None).
