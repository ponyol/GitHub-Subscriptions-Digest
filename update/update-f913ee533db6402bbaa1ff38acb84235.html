Fixes #17935 - ci: fix GPU push-event refspec and stabilize required checks (#17976) * ci: fix GPU test workflow on push events The test_gpu.yml workflow is triggered by both pull_request and push events, but the checkout step hardcoded `git fetch origin pull/${PR_ID}/head:ci_build`. On push (and workflow_dispatch), github.event.pull_request.number is empty, so the refspec expanded to `pull//head:ci_build` and the job aborted with "fatal: invalid refspec". Branch the checkout on event type: PR events still fetch the PR head; push/dispatch events fetch and check out github.sha directly so we test the exact commit that triggered the run, not whatever HEAD the shallow clone happens to land on. Signed-off-by: Bvicii <yizhanhuang2002@gmail.com> * ci: always run GPU job when test_gpu.yml itself changes The detect-changes filter skips GPU tests when only *.yml files change, but that prevents this workflow from being validated on a PR that edits itself. Since test-pr-gpu is a required check, a SKIPPED conclusion leaves the PR blocked on an unsatisfiable required status. Add a fast-path: when .github/workflows/test_gpu.yml is among the changed files, force skip_gpu=false so the job runs. Signed-off-by: Bvicii <yizhanhuang2002@gmail.com> * ci: stabilize required checks via aggregator pattern Branch protection on `main` requires three status contexts to report SUCCESS: `check-code-style`, `test-pr`, `test-pr-gpu`. Two of those are currently unreliable: 1. `test-pr` is a phantom — `tests.yml` defines it as a matrix job, so the actual check runs are named `test-pr (3.8)`, `test-pr (3.9)`, `test-pr (3.13)`. None match the literal `test-pr`, so the required context never reports and PRs hang on a check that will never come. 2. `test-pr-gpu` reports SKIPPED on docs-only / yml-only changes (since `detect-changes` filters those out), and a SKIPPED conclusion does not satisfy a required-check rule, so those PRs are also blocked. Fix both with the same shape — split the heavy job into an `-impl` sibling and add a thin aggregator that owns the required name: - `tests.yml`: matrix renamed to `test-pr-python`; new `test-pr` job always runs, exits 0 for docs-only PRs, otherwise propagates the matrix result. - `test_gpu.yml`: GPU job renamed to `test-pr-gpu-impl`; new `test-pr-gpu` job always runs on ubuntu-latest, exits 0 when the skip flag is set, otherwise propagates the GPU job's result. The actual python and GPU work is unchanged — only the check name that branch protection observes is moved to a guaranteed-reporting wrapper. This avoids needing admin access to update branch protection. Signed-off-by: Bvicii <yizhanhuang2002@gmail.com> --------- Signed-off-by: Bvicii <yizhanhuang2002@gmail.com>
