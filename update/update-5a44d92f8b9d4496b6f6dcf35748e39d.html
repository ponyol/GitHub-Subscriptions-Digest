Суммаризация (на русском)

Это обновление исправляет проблему производительности в сессиях ONNX Runtime GPU для операций свертки, особенно влияющую на PP-OCRv5. Оно меняет опцию `cudnn_conv_algo_search` с "DEFAULT" на "HEURISTIC", поскольку "DEFAULT" часто приводила к медленному резервному пути и задержкам до 50 раз выше из-за отклонений алгоритмов cuDNN. Новый подход "HEURISTIC" динамически выбирает поддерживаемый алгоритм, что значительно снижает задержку и сокращает время холодного старта, обеспечивая производительность, сопоставимую с "EXHAUSTIVE", но без его недостатков для динамических форм.

- fix(onnx): use HEURISTIC cudnn_conv_algo_search for ORT GPU session (#17970) * fix(onnx): use HEURISTIC cudnn_conv_algo_search for ORT GPU session The ONNX Runtime CUDA EP option was set to "DEFAULT", which pins cuDNN to CUDNN_CONVOLUTION_FWD_ALGO_IMPLICIT_PRECOMP_GEMM. For many of PP-OCRv5 server rec's conv configs cuDNN rejects this algo and ORT falls back to a non-cuDNN slow path (visible as "OP Conv(...) running in Fallback mode. May be extremely slow." warnings), making steady-state per-shape latency ~50x higher than necessary. "HEURISTIC" picks a supported algo per node via cudnnGetConvolutionForwardAlgorithm_v7, matching the fix landed in PaddleX#5057 for the ultra-infer C++ ORT backend. Benchmark on PP-OCRv5 server rec ONNX (RTX 2080 Ti, onnxruntime-gpu 1.20.0, CUDA 12.6 / cuDNN 9), shapes [B,3,48,W]: mode cold total steady (1,160) (4,320) (8,480) DEFAULT 4556 ms 206.05 ms 209.31 220.40 HEURISTIC 1488 ms 4.27 ms 9.54 24.96 EXHAUSTIVE 1424 ms 4.17 ms 9.73 24.84 HEURISTIC matches EXHAUSTIVE quality without the per-new-shape benchmark cost EXHAUSTIVE incurs on dynamic-shape OCR workloads.
