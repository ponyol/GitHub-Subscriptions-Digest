Суммаризация (на русском)

Это обновление вносит существенные изменения в язык Mojo, включая отказ от ключевого слова `fn` в пользу `def` со спецификаторами `raises` и стандартизацию расширения файла `.mojo`. Значительные оптимизации производительности были применены к конвейерам моделей, таким как FLUX и Flux1, повышая эффективность ядер с помощью таких функций, как пакетное умножение матриц и улучшенное управление памятью. Выпуск также добавляет поддержку новых моделей, таких как DeepSeekV3.2 и Kimi2.5, наряду с обширным рефакторингом кода и улучшениями в документации.

MODULAR_ORIG_COMMIT_REV_ID: f9fc70de554561d618f1fa29aa842de04edf7d14 - [Models] Eliminate EagerRealizationContext overhead in FLUX.2 text encoder Two optimisations to the FLUX.2 text encoding path, plus removal of an intermediate workaround now that the root cause has been fixed upstream: 1. Fuse `_prepare_prompt_embeddings` into `Mistral3TextEncoderTransformer. forward()`. The stack/permute/reshape that prepared the prompt embeddings was previously a separately compiled graph, requiring the text encoder to materialise three intermediate GPU tensors and pay a second graph-launch overhead. The ops are now part of the text encoder's single compiled graph. 2. Derive `seq_len` and `batch_size` from the input token array rather than calling `map(int, prompt_embeds.shape)` on the output tensor, which forced a host-device sync while the GPU was still computing. 3. Remove the `unwrap_model()` workaround from both the Flux1 and Flux2 pipelines and from `ComponentModel` entirely. Previously, `Module.compile()` returned `F.functional(session.load(graph))`, which created a new `EagerRealizationContext` on every inference call — compiling a trivial seed graph on every exit. The workaround bypassed this by unwrapping the compiled model to a raw `Model` and converting `driver.Buffer` outputs back to `Tensor` at each call site. The root cause has since been fixed in `Module.compile()` directly: it now returns a lightweight `_compiled` closure that calls the pre-compiled session model without any `EagerRealizationContext` overhead. With that fix in place, `ComponentModel.unwrap_model()` is removed entirely and the call sites in both pipelines are simplified to use `ComponentModel.__call__` directly, which already returns `Tensor` objects.
