This release introduces significant stability and performance enhancements, including fixes for stale reasoning effort leaking between model providers, preventing concurrent Crush instances from invalidating each other's logins, and ensuring race-free configuration access. Key performance improvements make model selection and config reloads much faster, alongside more reliable UI rendering for elements like the pills box. Additionally, provider interactions are improved through tool call JSON validation, accurate model discovery for local providers, and a faster, bounded glob tool for large directories. --- Этот релиз представляет значительные улучшения стабильности и производительности, включая исправления утечки устаревших параметров ReasoningEffort между поставщиками моделей, предотвращение взаимной аннуляции логинов между конкурирующими экземплярами Crush и обеспечение безопасного доступа к конфигурации без гонок данных. Ключевые улучшения производительности значительно ускоряют выбор модели и перезагрузку конфигурации, а также повышают надежность рендеринга элементов пользовательского интерфейса, таких как панель "pills". Дополнительно, улучшено взаимодействие с поставщиками благодаря валидации JSON для вызовов инструментов, более точному обнаружению моделей для локальных поставщиков и более быстрому, ограниченному инструменту glob для работы с большими директориями.

- chore: auto-update files - fix(config): prevent stale ReasoningEffort from leaking across providers (#3209) When a user selects a model from a different provider than the auto-detected default, the default provider's ReasoningEffort (e.g. anthropic's "high") was leaking into the selected model. Now when the user doesn't explicitly set reasoning_effort, the selected model's own DefaultReasoningEffort is used instead. - chore(legal): @feizhuzheng has signed the CLA - v0.80.0 - fix: render pills box reliably when todos or queue appear mid-session The pills panel only drew when layout.pills had vertical space, but that space was reserved by updateLayoutAndSize which ran only on explicit triggers (toggle, resize, in-progress flip). When the model created new todos while the panel was collapsed, the layout never recomputed and the box stayed invisible until ctrl+t forced it. Re-render pills on every Draw pass so the box appears as soon as content exists, regardless of whether the layout footprint changed. - fix(auth): stop two Crush instances from invalidating each other's login When two Crush instances shared one OAuth login (for a provider that rotates refresh tokens, like Hyper), they could each refresh the token on their own schedule. Because each refresh retires the previous token, the two instances kept revoking the credential the other was using, producing endless "authentication failed" errors even though every refresh reported success. Token refresh is now coordinated so only one refresh happens at a time, both within a single process and across processes sharing the same login. Any instance that finds the credential was just refreshed by another adopts that result instead of refreshing again, so concurrent instances converge on one working token instead of cannibalizing each other. - fix(config): make concurrent config access race-free via copy-on-write Reading the active config raced with writes that mutated it: Config() handed out a pointer with no synchronization while reloads swapped it and typed setters (compact mode, preferred model, docker MCP, ...) mutated its fields in place. The race detector flagged both during concurrent startup and settings changes. Config is now published copy-on-write. Reads are guarded so they always see a fully constructed snapshot, and every mutation clones the current config, changes the clone, and atomically swaps it in. Because published configs are never mutated in place, a reader holding an older pointer keeps reading a consistent snapshot instead of racing a writer. A single write lock now serializes all config-producing operations (typed setters and reloads), replacing the narrower reload-only lock, so two writers can no longer lose each other's updates. This keeps model selection fast — it still skips the expensive full reload — while closing the remaining data races. - perf(config): make model selection and config reload fast Model selection wrote config and then triggered a full reload of every config file, the provider catalog, and agents on each pick, which scaled with the number of configured models and made switching sluggish. Selecting a model now persists without the redundant full reload, since the in-memory state is already updated and agents are rebuilt separately. The reload path itself is also much faster: the static LSP defaults catalog and the git worktree root are cached instead of recomputed, literal config values skip shell expansion entirely, the working directory is resolved only when a command substitution needs it, and AWS credential file probing no longer stats the filesystem during tests. - perf(ui): skip theme rebuild when provider keeps the same theme - feat(ui): optimize model ui rendering - fix: validate tool call JSON before storing to prevent stuck conversations Malformed tool call arguments from providers (e.g. GLM-5.2 via vLLM) were persisted as-is, causing every subsequent resend to fail with a parse error. Sanitize input at the streaming callback boundary, replacing invalid JSON with an empty object and logging a warning.
