Raw XML leaking into user messages Cursor agent wraps the user's actual query in an XML envelope and appends large context blobs: <user_query>do something</user_query> <context>...hundreds of lines...</context> The old parser passed the entire text block through unchanged, so CCHV displayed the raw XML tags and the verbose context dump. Fix: `clean_user_text()` strips the outer `<user_query>` wrapper and truncates everything after the first `</user_query>` close tag, then strips any remaining XML-style tags so the viewer shows only what the user actually typed. ## 2. [REDACTED] noise Cursor redacts sensitive file contents with `{"type":"redacted", "data":"[REDACTED]"}` content blocks (or a `text` block whose sole content is the literal string `[REDACTED]`). Messages that consist *only* of redacted blocks appeared in the conversation list as "[REDACTED]" entries with no useful information. Fix: `is_only_redacted()` detects these messages; they are silently skipped so they do not pollute the conversation view. Mixed messages (where at least one non-redacted block exists) are still shown. ## 3. Missing shell / tool output Cursor stores command results in `{"type":"tool_result"}` and `{"type":"command_output"}` content blocks alongside the usual `text` blocks. The old `extract_text()` helper only picked up `text` blocks, so the tool output side of the conversation was invisible. Fix: `extract_text_all_blocks()` now collects text from: - `{"type":"text", "text":"..."}` — normal prose - `{"type":"tool_result", "content":[...]}` — nested content array - `{"type":"command_output", "output":"..."}` — shell stdout/stderr The session-title helper (`extract_text`) retains the old narrow behaviour (title derived from the user's typed query only, not from tool noise), while `convert_message` now calls `extract_text_all_blocks()` so rendered message content is complete. ## Tests Five new unit tests cover every new code path: - `clean_user_text_strips_wrapper_and_context` - `clean_user_text_no_wrapper_passthrough` - `redacted_only_message_is_skipped` - `mixed_redacted_message_is_kept` - `tool_result_and_command_output_extracted` All existing tests pass unchanged.
