This update introduces several new features, including an initial RNG seed for AArch64 guests via FDT, MTU advertisement for virtio-net, and VIRTIO_RING_F_EVENT_IDX support for virtio-vsock. The sandbox tool now allows custom kernel boot arguments and supports diverse root filesystems. Key improvements include fixing interrupt ID leaks on device hot-unplug, enhancing FDT validation, and switching the default guest kernel to version 6.1. Это обновление представляет несколько новых функций, включая начальное зерно RNG для гостей AArch64 через FDT, объявление MTU для virtio-net и поддержку VIRTIO_RING_F_EVENT_IDX для virtio-vsock. Инструмент sandbox теперь позволяет передавать пользовательские аргументы загрузки ядра и поддерживает различные корневые файловые системы. Среди ключевых улучшений — исправление утечек ID прерываний при горячем отключении устройств, улучшение проверки FDT и переключение ядра гостевой системы по умолчанию на версию 6.1.

- changelog: add note about `rng-seed` FDT node Mention addition of new FDT node with initial random seed for the guest. Signed-off-by: Egor Lazarchuk <yegorlz@amazon.co.uk> - vmm: aarch64: provide initial RNG seed via FDT Older aarch64 machines may not have hardware random generators. Because of this it takes a lot of time for the entropy to built up naturally in VMs booted on such hosts. To mitigate this add `rng-seed` FDT node which will contain 64 bytes of the initial seed guest can use. Note about x86_64: Since we only support FDT on aarch64, this is aarch64 only solution. On x86_64 the only option we have is to use `SETUP_RNG_SEED` setup_data section in the Linux boot protocol. The problem with it is that it only works with Linux boot which is less preferable than PVH boot (which does not support setup_data and thus `SETUP_RNG_SEED`). Additionally there is no ACPI support for providing initial seed as well. The only proper way to do this on x86_64 is to use EFI, which we don't do right now. When set, the virtio-net device advertises VIRTIO_NET_F_MTU and places the value in config space at offset 10 (matching the virtio_net_config layout), allowing the guest driver to configure the interface MTU automatically.
