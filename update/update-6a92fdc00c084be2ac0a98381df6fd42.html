Суммаризация (на русском)

Недавние обновления включают оптимизацию Makefile за счет удаления неиспользуемых и неисправных хуков для Windows, что делает его предназначенным только для Linux/MacOS и упрощает поддержку. Были внесены улучшения в функциональность `drop_table()`, предусматривающие многофазное удаление, добавление транзакционного состояния и улучшение действий по накату каталога. Кроме того, было реализовано изменение протокола для публикации существующих версий, а также новая валидация для `table.md`.

Исходный текст

- Changes to protocol to handle publishing existing version (#938) Adding validation for table.md to have at least one entry - Streamline Makefile (#937) No one seems to be using or maintaining the Windows hooks in our Makefile, and they're already broken in several places. This backs them out so that the Makefile is once again Linux/MacOS only, which streamlines the Makefile and makes it easier to maintain. If Windows support becomes important again we'll need to redo it anyway. (This won't affect any customers using Pixeltable on Windows.) - Multi-phase drop_table() (#932) In order to accommodate multi-phase drop: - adds more transactional state to TableMd - adds roll-forward action to Catalog - changes initialization of StoreBase to avoid references to a view's base (so that the sa_table of a StoreView can be initialized w/o the base table still being present)
