Суммаризация (на русском)

Обновление представляет новые модели Grok (`grok-4.3`, `grok-build-0.1`) и расширяет поддержку моделей, включая `claude-fable-5` и `claude-opus-4.8` через GitHub Copilot. Существенным изменением является переработанная логика перенаправления в `gptel-buffer`, которая теперь позволяет вставлять запросы и отправлять их из буфера gptel, обеспечивая непрерывные беседы из любого буфера Emacs. Кроме того, улучшена обработка инструментов для обеспечения согласованности, и добавлены предупреждения о безопасности в отчеты об ошибках относительно ключей API.

All Grok models available through the API have been either deprecated, removed or aliased to one of these two. - gptel-request: Make gptel-get-tool idempotent * gptel-request.el (gptel-get-tool): When passed a gptel-tool object, return it as is. This is to ensure that forms like (mapcan #'gptel-get-tool tools) always returns a list of gptel tools when tools is of mixed type, i.e. contains both tool names and tool objects. - gptel-transient: Update gptel-buffer redirection logic Change how gptel-menu's "redirect to gptel buffer" ("g" option) works. Before, the gptel buffer only served as the sink for the response. From experience, that this is rarely of any use. Now the prompt (from whatever source) is inserted into the gptel buffer and the request is sent from the gptel buffer, effectively continuing the conversation in that buffer. The advantage of this approach is that you can now have a conversation in a gptel buffer from anywhere in Emacs without having to switch to it first. * NEWS (Breaking changes): Mention change. * gptel-request.el (gptel-request): When the prompt is nil, meaning that the prompt is to be inferred from the buffer, it was previously always constructing the prompt from the current buffer.
