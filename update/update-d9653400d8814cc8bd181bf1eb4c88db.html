- docs: clarify org-agenda-files setup for existing users The README's suggested (setq org-agenda-files (list org-gtd-directory)) silently overwrites any existing org-agenda-files and obscured that a directory is a valid entry. Add guidance to merge via add-to-list and note that a directory entry scans every .org file inside it. Refs #278 - fix: preserve point when creating refile target (#288) Re-organizing an item already in org-gtd-tasks.org (e.g. org-gtd-someday on a next action) raised "Cannot refile to position inside the tree or region" or moved the wrong subtree. When the missing refile target was created, org-gtd-refile--add-target left point at end-of-buffer. Because the item being organized lives in that same buffer, with-current-buffer does not restore point, so the subsequent org-refile acted on the wrong heading. Wrap the body in save-excursion to preserve point. - fix: preserve outline level on clarify-in-place (#291) In-place clarify write-back inserted the WIP subtree's text verbatim, but the WIP buffer always holds the subtree at level 1 (org-paste-subtree forces level 1 when pasting into an empty buffer). A nested heading was therefore promoted to level 1 on write-back. Re-level the clarified subtree to the original heading's outline level via org-paste-subtree instead of a raw insert. Refile was unaffected because org's refile engine already re-levels under the target. - fix: refresh agenda display on state change (#289) State-change actions in org-gtd-agenda-transient used org-todo via the item marker, which updated the underlying Org file but left the agenda line showing the stale keyword. Route them through a shared --change-state helper that uses org-agenda-todo (refreshes the agenda line and every line referring to the same heading) and then saves the buffer, preserving org-gtd's immediate-save convention. Add tests asserting the agenda line itself reflects the new state. - docs: guard against auto-pushing master (triggers MELPA deploy) - chore: replace bd (beads) with yaks for issue tracking Switch from bd/beads to yaks (yx) across all project configuration and documentation. The View Builder epic has been migrated to yaks; all property-filter issues were already implemented and are dropped. - chore: scope elisp-syntax PreToolUse hook to .el files only Gate the validate_elisp_syntax.py hook on Write/Edit/MultiEdit with an `if` glob (e.g. Write(**/*.el)) so it only fires on elisp files, and use $CLAUDE_PROJECT_DIR for an absolute hook path so it resolves correctly under subagent working directories (relative path was exiting non-zero and blocking unrelated Write/Edit calls). - docs: adjudicate 7 implementation-gap decisions (G-series) Interview-resolved the 7 previously-unplanned gaps from the implementation-status audit: - REF-02 guided three-phase reflect -> IMPLEMENT (guided walkthrough reusing someday-review session; configurable phases + mind-sweep + named cadence profiles) - REF-06 system maintenance / elevated reviews -> IMPLEMENT (org-gtd-setup opt-in recurring tasks; cadence kept orthogonal to altitude) - HOR-07 unified six-horizon view -> DROP (over-literal; not in the books) - HOR-06 personal credo/principles -> DOCS (horizons.org H5) - HOR-03/04/05 linkage -> IMPLEMENT (optional hooks like area-of-focus; de-dup areas-of-focus between horizons.org and config) - ORG-DEL-03 -> IMPLEMENT reframed (delegate a whole decomposed project) - CLA-06 -> already covered; spin off LLM-assisted clarify (v5/backlog) Adds spec-doc section 6 (G-series decisions table) and rewrites the audit's "unplanned gaps" section with dispositions.
