Суммаризация (на русском)

Это обновление упрощает настройку распределенного вывода (DI), унифицируя переменные окружения и требуя явного указания целевых конечных точек для запросов. Основные улучшения производительности включают значительно ускоренные ядра редукции GPU (до 3 раз), увеличение пропускной способности на 13% для рабочих нагрузок Qwen за счет оптимизации планировщика, а также начальную поддержку операторов сравнения SIMD в предложениях `where`. Релиз также исправляет критические ошибки, такие как состояния гонки в тестах с использованием нескольких GPU и проблемы с разделяемой памятью ZMQ при межузловой связи, а также добавляет функции квантования NVFP4.

Sample old env var: ``` MAX_SERVE_DISPATCHER_CONFIG='{"transport": "dynamic_zmq", "transport_config": {"bind_address": "tcp://10.0.0.207:7000", "default_destination_address": "tcp://10.0.0.229:6000"}}' ``` This is annoying since it is a json string and we need to take care due to double quotes and spaces. You can easily mispecify this due to string escaping woes. Additionally, it allows us to configure the transport type ("dynamic_zmq") when there are no other options. Finally, it allows us to pass the "default_destination_address". This refers to the default prefill node to forward a request by a decode node if the target endpoint is not specified for the request. This field is meaningless for prefill nodes since they do not forward requests. I am deleting this field and making it a hard error if target endpoint is not specified for a request.
