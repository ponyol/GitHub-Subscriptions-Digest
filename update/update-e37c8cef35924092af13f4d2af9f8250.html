Это обновление вносит критическое изменение, передавая контекст запроса функциям заголовков и URL бэкенда, что обеспечивает более динамичное взаимодействие с API. Its purpose is to delete ediff buffers such as the Ediff control panel. The current implementation of `gptel--rewrite-ediff' causes `gptel--ediff-restore' to be run before `ediff-cleanup-mess'. Since `ediff-cleanup-mess' expects to be run from the control buffer, this causes it to break. Move it further back in the hook. - gptel-request: Fix streaming responses on MacOS * gptel-request (gptel-curl--common-args): Response streaming (SSE) on MacOS appears to be broken since gptel started feeding request headers to Curl via STDIN instead. The reason for this is unclear. Fix by adding the -N (--no-buffer) Curl flag to `gptel-curl--common-args' on MacOS, which turns off Curl's output buffering. (#1339) - gptel-request: Fix macroexpansion of gptel--maybe-funcall * gptel-request.el (gptel--process-models): Expand arguments to macro correctly. (#1343) - gptel-gh: Update header to include 'x-initiator' * gptel-gh.el (gptel-make-gh-copilot): In the backend's header function, use the request state (INFO plist) to set the "x-initiator" header parameter to either "user" or "agent", depending on whether the request is new or a continuation turn containing tool results. The reason for this distinction is that these requests are billed differently by GitHub Copilot. (#1224) - gptel-request: Pass request context to header/url functions When the backend header or url is a function, it is now called with one argument: the request context (the INFO plist). This allows backends to modify their headers or target URL based on the state of the request, such as when following up on a tool call. A new macro `gptel--maybe-funcall' is used to retrieve the backend header and url, handling both functions and immediate values. gptel--maybe-funcall provides a temporary backward compatibility layer and a warning if there is an arity error (such as when the header/url functions don't yet accept the new argument.) This compatibility check will be removed in the gptel 1.0 release. * gptel-request.el (gptel--maybe-funcall): New macro to get the final value of variables that might store a value or a function.
