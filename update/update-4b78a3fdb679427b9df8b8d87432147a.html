Суммаризация (на русском)

Недавние обновления Tensorlake значительно упрощают асинхронные операции, убрав "Awaitables" и стандартизировав использование "Futures" для всех неблокирующих вычислений. Асинхронные функции Tensorlake теперь полностью соответствуют нативной модели `asyncio` Python, возвращая сопрограммы, которые можно ожидать или обрабатывать. Futures и сопрограммы также могут без проблем использоваться в качестве "tail calls" или входных данных для функций, при этом SDK автоматически управляет их выполнением. Дополнительно, новые методы, такие как `future.coroutine()`, улучшают интеграцию синхронных вызовов в асинхронную экосистему.

Future interface doesn't change. Users call future.result() to resolve it. Async Tensorlake functions can `await future` instead. Users can create futures manually the same way they were creating awaitables. Instead of calling function.awaitable(...) then need to call function.future(...). An `async` Tensorlake function always returns a coroutine object when called. This is 100% the same behaviour as with regular Python async functions. Sync function calling async functions will either have to create an asyncio event loop to run the couroutines (like any other regular Python sync funciton) or call the async functions using function.future(...) constructor and call future.resolve(). async code can just await a coroutine, as usual. This is fully compatible with python asyncio programming. async Tensorlake functions are detected as async functions by inspect module so async Agentic frameworks are able to call them correctly without any extra setup/wrappers needed. Coroutines and Future returned from async functions or created using function.future(...) don't start running immeditely. This is the same behavior as with python async functions. To run a Future user code needs to either call future.run() or future.result(). To run a coroutine user code needs to do asyncio.create_task(coroutine) or any other standard asyncio approach. As futures and coroutines don't start running immeditelly, they can be returned as tail calls. So we don't need a separate function.tail_call(...) interface anymore. A Tensorlake Future object, a Tensorlake async function coroutine and an asyncio.Task object created using asyncio.create_task(coroutine) can be passed as tail calls and can be passed as Tensorlake Function call, map, reduce operation inputs. SDK starts them automatically in this case if they are not running already. All traces of Awaitables were removed from code base so we now have a single Future class that represents all the computations internally. See the added tests on how exactly this all works.
