Core Pixeltable carries no OpenTelemetry dependency and never activates telemetry on its own; instrumentation lives in a separate distribution, opentelemetry-instrumentation-pixeltable, installable on its own or via the pixeltable[otel] extra. Pixeltable core exposes a small, dependency-free hooks layer that reports spans and events. When no subscriber is registered every call is a near-free no-op, so there is no overhead for users who do not opt in. The instrumentation package subscribes to those hooks and translates them into OpenTelemetry spans, metrics, and logs. Applications that already own an OpenTelemetry SDK can attach Pixeltable to their global providers with PixeltableInstrumentor().instrument(), and the standard opentelemetry-instrument CLI discovers it automatically via its entry point. Applications that want Pixeltable to build the providers and OTLP exporter can call init() once at startup. Configuration is read from the [otel] section of the Pixeltable config and overridden by the standard OTEL_EXPORTER_OTLP_* environment variables. The pxt serve command gains an --otel flag to enable instrumentation for a served app. This is part 1 of two. It establishes the hooks layer, the instrumentation bridge, and the initial span and metric call sites for the insert path (operation, planning, media, store, row, and UDF spans).
