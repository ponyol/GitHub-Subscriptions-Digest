Несколько обновлений улучшают разработку на Java, в том числе исправлена ошибка, из-за которой Eclipse JDTLS игнорировал допустимые имена пакетов (например, `dist`/`lib`/`classes`/`out`), а также решена проблема с резервным механизмом `JAVA_HOME` для импорта Gradle. Кроме того, процесс сборки сервера HLSL на macOS CI был стабилизирован благодаря использованию `cargo --locked` для управления зависимостями, а также был реализован патч безопасности, отклоняющий абсолютные или содержащие спецсимволы имена файлов памяти.

Several of these (dist, lib, classes, out) are valid Java package identifiers, so any source file whose package path contained one was dropped from directory traversal and became invisible to the symbol tools (find_symbol, get_symbols_overview, find_referencing_symbols) even when git check-ignore reported nothing. That release removed the public field GlslCompilationParams.preamble (split into preamble_path/preamble_content), which shader_language_server 1.3.1's server_config.rs still constructs, so the from-source build fails with E0560 and cargo exits 101. macOS is the only platform that builds the server from source (Linux/Windows download prebuilt release binaries), so only the macOS CI jobs fail: all 15 test/solidlsp/hlsl fixtures error at setup (run 28726267725, job 85184119276). --locked makes cargo honor the Cargo.lock packaged with the published crate, which pins shader-sense 1.3.1 - the dependency set the 1.3.1 release was built and tested from - and immunizes the build against future lockstep releases of the two crates. Verified locally: the unlocked build reproduces the exact E0560/exit-101 failure; the locked build compiles cleanly and yields a working binary reporting v1.3.1.
