Closes #278. 🤖 Generated with [Amplifier](https://github.com/microsoft/amplifier) Co-authored-by: Amplifier <240397093+microsoft-amplifier@users.noreply.github.com> - fix(ollama): treat OLLAMA_HOST=0.0.0.0 as a bind address and fall back to localhost (#521) `0.0.0.0` (and the IPv6 equivalent `[::]`) are wildcard *bind* addresses — servers listen on them to accept connections on every interface, but they are never valid as a *connect* target. On Windows in particular, the Ollama installer/service config commonly sets `OLLAMA_HOST=0.0.0.0` so that the daemon accepts non-loopback traffic, and that value then leaks into every child process's environment. When llmfit picked up `OLLAMA_HOST=0.0.0.0`, it built `http://0.0.0.0` and used that as the connect URL, which always fails — so the user saw "no Ollama found" even though Ollama was running fine on the same host. This commit detects wildcard hosts in the parsed `OLLAMA_HOST` value and ignores them with a warning, letting the existing default kick in (localhost → 127.0.0.1 fallback chain). Both IPv4 (`0.0.0.0`) and IPv6 (`[::]`, `[0:0:0:0:0:0:0:0]`) wildcards are handled, with or without scheme/port, and routable hosts that merely contain `0.0.0.0` as a substring are correctly left alone. Adds unit tests for the wildcard detector covering each case.
