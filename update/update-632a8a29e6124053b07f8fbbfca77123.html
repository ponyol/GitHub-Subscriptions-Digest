Это обновление значительно улучшает несколько компонентов Django, фокусируясь на повышении наблюдаемости, надежности и гибкости конфигурации. Ключевые изменения включают новую систему мониторинга состояния очередей RQ с расширенными метриками и оповещениями, а также миграцию конфигурации с YAML на модели Pydantic с добавлением правил маршрутизации баз данных. Кроме того, надежный оркестратор миграций для нескольких баз данных заменяет устаревший менеджер, обеспечивая проверку состояния, обнаружение расхождений и автоматическое исправление для сложных изменений схемы.

- refactor(django-rq): enhance RQ queue health monitoring - Add new `QueueHealthMonitor` class to orchestrate queue health checks - Introduce `QueueMetrics` and `QueueStatus` models to capture and evaluate queue metrics - Implement Redis-backed alert deduplication and cooldown - Add `rq_health_check` management command to run health checks manually - Refactor `django_rq.health` module for better testability and extensibility This change significantly improves the observability and reliability of the RQ queue health monitoring system. It introduces a structured approach to collecting, evaluating, and alerting on queue health metrics. - feat(django-cfg): add database routing rules for feature configs This change introduces a new mechanism to allow feature-level configurations to specify a non-default database alias for their models. The `DatabaseSettingsGenerator` now collects these rules and populates the `DATABASE_ROUTING_RULES` setting, enabling co-located queries for the app's domain models and the feature-specific data. Additionally, the `useSWRInfinite` and `useSWR` hooks have been updated to support an optional `enabled` flag in their config. This allows conditionally skipping data fetches for gated endpoints. - refactor(django-cfg): migrate configuration to Pydantic models - Switched from YAML-based configuration to Pydantic v2 models - Replaced `load_config()` with direct `DjangoConfig` instantiation - Updated `DatabaseConfig` fields and defaults - Added new fields for database connection management and routing - Replaced `GRPCConfig` with nested configuration under `DjangoConfig` - Standardized environment variable handling across configuration models - feat(django-migrator): introduce multi-database migration orchestrator This new module replaces the legacy MigrationManager with a more robust, state-validated orchestrator that can handle drift detection, automatic repair, and multi-database migrations. Key changes: - Added new django_migrator package with introspection, repair, and orchestration logic - Replaced MigrationManager with Migrator class that coordinates the migration lifecycle per database - Introduced drift detection to identify missing or unrecorded schema changes - Implemented automatic repair via fake-apply and fake-unapply operations - Enabled cross-database migrations with locking and state validation
