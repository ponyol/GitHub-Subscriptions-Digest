- Fix package-lint reserved key errors for inline image bindings The `C-c i ...` prefix used by the inline image zoom/save bindings violates Emacs key binding conventions: `C-c <letter>` sequences are reserved for users, so package-lint flagged 5 errors in eca-chat.el and broke CI across every matrix entry. Switch the prefix to `C-c C-z ...` (control-char following `C-c`, reserved for major modes; `z' for zoom). CHANGELOG updated to match. 🤖 Generated with [eca](https://eca.dev) Co-Authored-By: eca-agent <git@eca.dev> - Fix mode-line trust indicator corrupting redisplay in `emacs -nw` Since b6269e9 ("Simplify mode-line trust indicator to emoji-only") the chat mode-line unconditionally renders `🔥` / `🛡️` (U+1F525 / U+1F6E1+U+FE0F) on every frame, after that commit deleted the TTY-aware helper that picked a single-cell BMP fallback via `display-graphic-p`. On terminal frames Emacs's `string-width` for those codepoints frequently disagrees with the cell count the terminal actually paints, so the chat mode-line ends up off by one column. Emacs's TTY redisplay positions every other window relative to mode-line column counts, which is why a single off-by-one cascades into corrupt rendering across *all* Emacs windows --- not just the chat buffer --- as reported across ghostty, kitty, and Konsole. GUI frames are unaffected. Reintroduce TTY-safe defaults via two new defcustoms, `eca-chat-trust-on-symbol-tty` (default `●`) and `eca-chat-trust-off-symbol-tty` (default `○`); the `:trust` branch of the mode-line keyword renderer now selects between graphic and TTY symbols via `display-graphic-p`. Emoji defaults are preserved on graphic frames, and both groups remain customizable independently.
