The updates significantly boost system performance and reliability, primarily through the introduction of parameterized queries, plan caching, and thread-safe catalog operations, leading to substantial gains in query execution speed. Database stability is further improved by switching to `READ COMMITTED` isolation and fixing critical cache invalidation issues. Additionally, the changes enhance extensibility by allowing services to be deployed directly from code and streamline column initialization processes. General stability is also addressed through various test improvements and updates to model deprecations. --- Обновления значительно повышают производительность и надежность системы, в первую очередь за счет внедрения параметризованных запросов, кэширования планов и потокобезопасных операций каталога, что приводит к существенному увеличению скорости выполнения запросов. That 2nd step includes retargeting of `ColumnRefs`. This change folds everything in a single step in which `TableVersion` first fully prepares a value expr for each column, and only then creates a `Column` instance with it. Due to dependencies between columns and indexes, this is only possible if columns and indexes are initialized in lock-step. The broader context of this change is that it will make it easier to fix retargeting of `ColumnRefs` which is a blocker to my schema evolution work [PXT-969](https://pixeltable.atlassian.net/browse/PXT-969).
