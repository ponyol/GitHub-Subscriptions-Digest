Суммаризация (на русском)

Интерфейс просмотра дубликатов теперь полностью включает кнопки действий (объединить, заменить и т.д.), позволяя пользователям разрешать пары дублирующихся воспоминаний. Эти изменения записываются в журнал и управляются с помощью улучшенного API для обеспечения согласованного состояния. Также были внесены важные исправления: теперь выдается предупреждение вместо бесшумного отката к менее качественным встраиваниям TF-IDF при сбоях вызовов OpenAI API, а также предотвращена бесконечная анимация вращения в представлении графа путем обеспечения отключения физики после обновлений в реальном времени.

- Revert "feat(duplicates): wire action buttons — Block 4 of duplicate review UI" This reverts commit 4801e4d0584e27a46603db9ed3f1e2930e973b58. - feat(duplicates): wire action buttons — Block 4 of duplicate review UI Previously the Merge / Supersede / Keep both / Dismiss buttons in the Duplicates tab were disabled with "Not implemented yet". They now post the user's choice to a new POST /api/duplicates/resolve endpoint that: - Lazy-creates a `duplicate_resolutions` table in D1 on first write. - Upserts (lo_id, hi_id, action) — INSERT OR REPLACE lets users change their mind without having to dismiss first. - Logs a human-readable summary to `memories_actions` (attached to the "loser" side for supersede/merge, to the lower id for neutral actions) so the History tab shows the audit trail. GET /api/duplicates now reads `duplicate_resolutions` and skips any pair the user already handled — refresh/rescan stays consistent. UI changes in memora/graph/index.html: - Buttons enabled, each bound to resolveDupPair(a_id, b_id, action). - Optimistic removal from the in-memory list on successful response; badge count decrements. - Two explicit "#<id> supersedes" buttons instead of a single "Mark supersedes" — users can now say which side wins without first loading both memories. Scope note: this is a UI-level resolution only. Merging actual memory content or writing supersedes edges into memories_crossrefs is intentionally deferred — the MCP memory_merge / memory_link tools remain the authoritative path when the user wants to mutate the underlying graph. Partially closes memory #452 (Block 4).
