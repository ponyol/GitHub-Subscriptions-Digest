Layout: a `## Versions` section (same content as `eca-version` plus `system-type`) followed by a `## Chat` section sourced from the active session's chat buffer, auto-detected via the new internal helper `eca-chat--doctor-find-buffer` (tries the current buffer's session first, then falls back to the `last-chat-buffer` of any running session in `eca--sessions`). The chat section captures: inspected chat buffer name / `major-mode` / `derived-mode-p 'eca-chat-mode' / `eca-chat-parent-mode` / dir, the actual `key-binding` of RET / <return> / C-m sampled with `with-current-buffer` so it reflects the chat buffer's bindings rather than the report buffer's, likely shadowing minor modes (electric-pair/indent/quote, evil + state, viper, god, smartparens, paredit, corfu, company) and the current input method, ECA chat state (`eca-chat--id`, `eca-chat--closed`, `eca-chat--chat-loading`, `eca-chat--pending-question`, `(eca-session)` + id + workspace-folders), prompt-area / prompt-field overlay bounds + point + `(eca-chat--prompt-content)`, and a rule-based Hints section pointing at the most likely root cause (wrong major-mode, RET hijacked, no session, missing overlay, evil insert-state, pending question, closed chat). Motivation: issue #242 reports that hitting RET in the chat buffer only inserts a newline. `eca-chat--key-pressed-return` structurally cannot produce a newline — every branch either acts or returns silent nil — so the symptom must originate from keymap shadowing or major-mode misactivation in the user's environment. `eca-doctor` captures exactly the data needed to pinpoint such issues so future reports become self-serve without multi-round Q&A.
