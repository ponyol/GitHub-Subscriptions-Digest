Суммаризация (на русском)

Обновление включает крупный переход с неподдерживаемой библиотеки `bincode` на `bitcode`, что повлекло за собой корректировку пороговых значений памяти для снимков ВМ и обработку CRC снимков. Была проведена существенная реструктуризация для отвязки `VmResources` от `RuntimeApiController`, что улучшило горячее подключение устройств и внутреннюю архитектуру. Помимо этого, повышена производительность за счет включения AMD AVIC и выполнены плановые обновления зависимостей.

Signed-off-by: Nikita Kalyazin <kalyazin@amazon.com> - test(memory_monitor): provide separate thresholds When migrating from bincode to bitcode, when a snapshot is being taken the VM sometimes exceeds the 5 MiB RSS overhead threshold, mainly with a large number of CPUs (32 vCPUs). The threshold is still maintained when the VM is booted or restored. Introduce separate thresholds for booted, restored and VMs being snapshotted and increase the snapshotted threshold from 5 to 6 MiB. This is acceptable because the memory overhead increases only for a short period of time, even if the same VM is snapshotted multiple times. Signed-off-by: Nikita Kalyazin <kalyazin@amazon.com> - chore: migrate from bincode to bitcode Reason: the bincode crate is no longer maintained [1]. Notable changes made during the migration: - Since, unlike bincode, bitcode does not support with_fixed_int_encoding mode, the snapshot CRC field is now written as plain bytes to guarantee that its length is not going to change due to potential future changes in the serialisation logic. - Added a new argument to the seccompiler-bin to produce per-thread filter files to facilitate testing. Previously, the test_validate_filter was parsing the bincode-encoded filters itself. With individual per-thread filter files this is no longer required. Signed-off-by: Ilias Stamatis <ilstam@amazon.com> - rpc_interface: Remove MmdsRequestHandler trait A subsequent patch will make RuntimeApiController get the mmds object from self.vmm rather than self.vm_resources (which we want to get rid of). The problem is that the mmds() function of the MmdsRequestHandler trait returns a MutexGuard. Therefore we can't lock self.vmm in that function because we'll need to drop the lock at the end of the function while trying to return a MutexGuard for the Mmds which is part of the Vmm's state protected by the firt lock. Rust will rightly complaint and won't let that happen. Get rid of the MmdsRequestHandler trait and simply have the caller pass a MutexGuard for the Mmds as an argument to the functions (unfortunately it has to be a MutexGuard since that's the type returned by locked_mmds_or_default()). No functional change intended. Signed-off-by: Ilias Stamatis <ilstam@amazon.com> - rpc_interface: Remove runtime mmds unit tests The test_runtime_{put,patch}_mmds() tests are almost identical to the test_preboot_{put,patch}_mmds() tests. The only difference is that the 'runtime' ones test that the RuntimeApiController correctly dispatches the API calls. But we already have python integration tests (see test_config_with_default_limit()) that test this. The firecracker API allows for weird things such as getting and setting values from/to the MMDS post boot even if no network interface is bound to it. Since the API doesn't let you bind a network interface to the MMDS after the VM is booted, that means MMDS calls will create an MMDS object that will be completely unreachable from the VM. This is what allows the test_runtime_{put,patch}_mmds() tests to succeed currently. However, that weird API behaviour is going to be fixed by a subsequent patch which would make these tests fail. We could configure these unit tests to use VM with network interfaces that are bound to the MMDS, however that's easier said than done. The default_vmm() method used for creating Vmm objects for tests doesn't create or consume any VmResources object which is required for creating an MMDS and binding it to a network interface before booting. Signifcant changes would be required to make that work. Simply remove the test_runtime_{put,patch}_mmds() unit tests since essentially they don't test anything that is not already covered by other tests.
