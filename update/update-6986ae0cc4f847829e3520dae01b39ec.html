Суммаризация (на русском)

Версия Flet 0.85.2 представляет значительные улучшения для `flet.Router`, добавляя флаги маршрутов `modal` и `recursive`, а также усовершенствованный механизм всплытия (pop) на основе цепочки. Флаг `modal=True` позволяет отображать представления в виде полноэкранных диалоговых окон-наложений, не заменяя базовый стек, в то время как `recursive=True` дает возможность маршрутам соответствовать своим собственным потомкам, создавая многоуровневые стеки представлений для сегментированных URL. Обновленный `on_view_pop` использует надежный подход на основе цепочек для навигации, а также релиз включает исправление, предотвращающее повторное использование сессии при активном соединении.

- docs: add 0.85.2 changelog entry for #6513 session reuse fix (#6518) - feat(router): add `modal`/`recursive` Route flags + chain-based pop (#6516) * feat(router): add `modal`/`recursive` Route flags + chain-based pop Three coordinated additions to `flet.Router`: - `Route(modal=True)` renders the route's View as a fullscreen-dialog overlay on top of the previous (non-modal) location's view stack instead of replacing it. Two flavours by placement: top-level (global, state-tracked base) and nested-child (local, URL-encoded base). Pop navigates to the base URL stamped on the View at emit time, so the underlying stack never rebuilds — no flash on close. - `Route(recursive=True)` matches itself as its own descendant. One View per consumed URL segment, so `/folder/a/b/c` produces a 4-View stack and back-swipe walks one segment at a time. Non-recursive children are tried before self-recursion at every depth, so a specific sibling (e.g. `example/:gp*`) wins over the recursive `:slug` without duplicating it at every level. - Default `on_view_pop` uses the matched chain's parent (`chain[-2].resolved_path`) instead of `views[-2].route` — robust against apps that share a `View.route` between sibling tab roots to suppress switch transitions. Each sub-chain (base + modal) now renders with its own `LocationInfo`, so `is_route_active(...)` inside a base view sees the base URL while a global modal is open over it. Docs (controls/router.md, cookbook/router.md), examples (modal_routes/, recursive_routes/), and tests (15 unit, 2 integration) added.
