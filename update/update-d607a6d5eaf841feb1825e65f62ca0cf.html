Суммаризация (на русском)

Это обновление представляет новую функцию пользовательского интерфейса, отображающую использование токенов (отправленных, кэшированных, полученных) непосредственно в строке заголовка буфера `gptel`, с переработанной внутренней системой отслеживания токенов для большей ясности и детализации. Также включены важные исправления логики подтверждения вызовов инструментов и корректной вставки имен инструментов. Дополнительно добавлена поддержка новых моделей Deepseek, а также различные мелкие исправления ошибок и улучшения документации.

Change 1: As before, the token counts are captured in a plist with keys :input, :output, :cached and :cache, but the meanings have changed slightly. - :input refers to tokens in the portion of the prompt that isn't cached. - :cached refers to tokens in the portion that is. Change 2: The request INFO plist now has two keys, :tokens and :tokens-full, corresponding to the token usage for that tool-use turn and the full ongoing request respectively. :tokens is needed since we want to be able to update and show the "live" session/buffer token count after each tool call in gptel's UI. :tokens-full is not needed by gptel's UI (since we sum :tokens in the gptel-buffer), but included for easy introspection of the FSM at the end of a request when using the `gptel-request' API. Without :tokens-full the FSM would only contain the token usage for the latest turn.
