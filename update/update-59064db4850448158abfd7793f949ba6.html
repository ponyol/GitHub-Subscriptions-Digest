Deepseek triggers a weird edge case in DP scheduler when max_batch_size is larger than prefill_chunk_size. This is because currently max_batch_size=512 and prefill_chunk_size=128. The prefill_chunk_size is low since the model is still under development. All other models use a larger value for prefill_chunk_size so this edge case never materializes. The bug manifests in the following way: - Replica 1: TG w/ 512 reqs with 512 inputs tokens for 10 steps - Replica 2: CE w/ 1 req with 128 inputs tokens for 1 step Then we merge these two batches into a mega batch: - Replica 1, 2: CE w/ 513 reqs and 640 inputs tokens for 1 step The "merge" just takes the min num_steps from each replica. And if any replica batch is CE, then the mega batch is CE. Clearly this mega CE batch is illegal since 640 input tokens > prefill_chunk_size * dp To avoid this, we just make it illegal to have max_batch_size larger than prefill_chunk_size On a aside, it may be worthwhile to rename `prefill_chunk_size` to `max_num_batched_tokens` since the value now imposes a limitation of TG as well. `max_num_batched_tokens` is used by vLLM et al. At the very least `target_tokens_per_batch_ce` needs to be renamed to be consistent with pipeline config. MODULAR_ORIG_COMMIT_REV_ID: f53e3aa9956ab08de34fe67897727a8bf7cf677f - [KVCache] Massive refactor of KVCache graph construction This PR simply moves `.get_symbolic_inputs()` from `kv_manager` to `kv_params`. This allows one to construct the graph purely with `kv_params` without needing the whole manager. The whole manager comes with a ton of baggage like needing a realized `Device` (not just a `DeviceRef`) and allocating a whole bunch of KVCache memory. This PR works towards getting rid of the NullKVCacheManager. The NullKVCacheManager essentially allows for graph construction via `.get_symbolic_inputs()` but does not allocate memory. In a later PR, we will just simply use kv cache params for graph construction instead. This shift of more responsibility to the `kv_params` means that the params need `devices : list[DeviceRef]` instead of just `n_devices : int`. This required a TON of plumbing for each model to achieve. Future PRs will follow up and clean up the plumbing. One ugly thing is that now we pass the kv_cache_params `list[DeviceRef]` to the constructor of KVCacheManager as well as a `list[Device]`. This is redundant! I think we should just have the following in the future: ``` kv_manager = params.build_manager() ``` MODULAR_ORIG_COMMIT_REV_ID: 4bfa08b42957d838435909fd687b2585b99933a2 - [docs] Remove unneeded code checks This is already automated.
