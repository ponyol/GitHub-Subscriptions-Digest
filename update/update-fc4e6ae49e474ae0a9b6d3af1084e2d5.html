- Bump graphiti-core version to 0.29.1 (#1499) Patch bump covering the fixes and forward-port that landed after the 0.29.0 release: attribute-hallucination guards, combined-extraction precision improvements, saga episode-time watermarks (#1498), MCP provider extras in Docker images (#1461), FalkorDB volume mount fix (#1462), and uv group dependency bumps (#1473). Server and MCP server graphiti-core requirements will be bumped after the 0.29.1 release is published to PyPI. Co-authored-by: Claude Opus 4.7 (1M context) <noreply@anthropic.com> - Forward-port: attribute-hallucination guards, combined-extraction precision, saga episode-time watermarks (#1498) * fix: prevent attribute hallucination bleed into graph fields Customer reported up to 9KB of LLM meta-reasoning landing in entity attribute fields (phones, industry) — the LLM was dumping its internal deliberation and echoing schema description text back into values. Three layered defenses: 1. Strengthen extract_attributes prompts (nodes + edges) with hard rules forbidding parenthetical reasoning, deliberative phrases, candidate alternatives, schema-description echoes, and "null"/"N/A" sentence stand-ins. Positive/negative examples included. 2. Add an OUTPUT DISCIPLINE block to the combined extraction prompt to close the "topic-as-Person" failure mode (full-sentence entity names like "Establish a firm training/onboarding program") and pre-empt reasoning leaks into fact text and relation_type. 3. Add a shared attribute-extraction preamble plumbed through each concrete provider override (OpenAI / Anthropic / Gemini / GLiNER2) via _apply_attribute_extraction_preamble on LLMClient, mutating the system message so the "field descriptions are format specs, not values" instruction reaches every production provider regardless of how structured output is wired. Sentinel-based idempotency. Plus a structural backstop: cap_string_attributes drops any string attribute >250 chars (configurable per-field via Field max_length, or globally via GRAPHITI_ATTRIBUTE_MAX_LENGTH) before it reaches the graph. list[str] cap support: per-item and aggregate (max_len * 8) length checks; aggregate-axis trigger is reported distinctly so DataDog lines don't look like a misconfigured cap. Required-field carve-out retains the value with a louder WARNING rather than dropping (would otherwise ValidationError the whole entity). Edge attribute writes use scoped merge for over-cap drops only — fields the LLM legitimately omitted still clear. Unified apply_capped_attributes(merge_mode='overlay'| 'replace') helper makes the node/edge merge asymmetry explicit at each call site. group_id flows to the log line for tenant correlation. * feat(prompts): improve combined extraction entity precision and edge quality Targets six classes of low-quality entities surfaced in an extraction review (multi-choice fragments, clock times, quantities, coordinates, imperative tip phrases, slogans) plus two systematic edge regressions (location-fragmentation through scenery intermediaries, dropped multi-episode setup facts). Changes to ENTITY RULES: - Rule 6 expanded into 8 sub-bullets covering the targeted skip classes, with concrete examples per class - Rule 9 added for didactic / tutorial scaffolding Changes to FACT RULES: - Rule 4 strengthened to call out narrative announcements, forward commitments, plans, and emotional setup as real facts in conversational episodes - Rule 8 added requiring direct speaker-to-target edges over fragmenting through scenery / observed-feature intermediaries Negative examples block (A-G) added with paired source-and-extraction guidance per class. Locomo 500-example evaluation (prompt change only): - Entity F1: 0.674 (flat); precision -0.028, recall +0.025 - Edge volume: +7.7% over baseline; gold-edge recall +0.9pp - Fact-text Jaccard on matched edges: 0.341 -> 0.381 - Targeted entity classes suppressed on LME-derivative sample: quantities -93%, imperative tips -40% * feat(saga): use episode reference time for saga summarization watermark Saga (thread summary) timestamps were being stamped with wall-clock time instead of the originating episode's reference timestamp. Saga changes: - _get_or_create_saga: rename `now` to `created_at`; callers now pass the episode's valid_at (== reference_time) so a newly minted saga's created_at matches the episode that produced it. - saga_get_episode_contents (graph_operations interface + implementations): return list[(content, valid_at)] tuples so the caller can compute the episode-time watermark. SagaNode now carries two watermarks with deliberately different roles: - last_summarized_at (wall-clock): the *filter* watermark. summarize_saga picks up any episode whose created_at > this value. Wall-clock + created_at comparison keeps backfilled episodes reachable on the next run (valid_at < watermark, created_at = now). - last_summarized_episode_valid_at (episode time): the *temporal* watermark. Maximum valid_at across the episodes covered by the current summary. Public/temporal consumers ("how recent is this summary's content in event-time?") should use this field; advances monotonically. Changes: - nodes.py + node_db_queries.py: add last_summarized_episode_valid_at field with persistence and read-back wiring (save query, SAGA_NODE_RETURN, get_saga_node_from_record). - summarize_saga: filter is e.created_at > $since and last_summarized_at = utc_now(); set last_summarized_episode_valid_at = max(valid_at) of just-summarized episodes (advancing only forward). - saga_get_episode_contents: filter remains ep.created_at > since while return shape widens to (content, valid_at) so the caller can populate the new field. * style: ruff format
