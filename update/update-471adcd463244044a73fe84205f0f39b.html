Система получила значительные обновления в различных модулях. Основные нововведения включают поддержку архитектуры Mamba SSM с новыми ядрами селективного сканирования и причинной свертки 1D, а также значительные оптимизации производительности GPU для SM100 (Blackwell/B200), такие как структурированная свертка 2D, слияние добавления остатка и новая инфраструктура TMA аппаратного Im2col. Фреймворк MAX теперь полностью поддерживает Eager Tensor API для операций интерпретатора, включает новые методы `Tensor` и предлагает настраиваемые стратегии планирования пакетов для генерации текста. Было повторно включено множество GPU-тестов для macOS, а также выполнены различные внутренние рефакторинги и очистки.

MODULAR_ORIG_COMMIT_REV_ID: 469b9bb329f62d63c4c01f7979623939bc7ec930 - [Kernels] Add `LayoutTensorIter` initializer from `Int` bound (Part 12.1/N) As part of removing implicit conversions from `Int` to `SIMD`, I ran into a tricky case with the `LayoutTensorIter(..)` constructor. This adds a new `LayoutTensorIter.__init__(ptr, bound: Int)` initializer, as a workaround for forcing the user to spell a complex conversion from `Int` to the `LayoutTensorIter.linear_uint_type`. The issue is that `LayoutTensorIter` currently has a commonly used constructor with this signature: fn __init__( out self, ptr: LegacyUnsafePointer[ Scalar[Self.dtype], address_space = Self.address_space, origin = Self.origin, ], bound: Self.linear_uint_type, ⚠️ # ... ) the tricky part is that `bound: Self.linear_uint_type` uses an associated comptime type that is computed based on the `LayoutTensorIter` parameters themselves, meaning that for a user calling the `LayoutTensorIter` constructor, they have no way to reference that comptime by name, since it doesn't exist at the time of passing arguments to the constructor. It's a weird circular dependency, with no simple "closed form" way of spelling the necessary type to cast to. You can spell out the explicit cast to the destination type "manually", but it uses several private internal helper functions, and is not pretty or intuitive: ```diff var input_smem = LayoutTensorIter[ input_dtype, input_cta_tile_layout, MutAnyOrigin, address_space = AddressSpace.SHARED, alignment=128, ]( input_smem_ptr, input_smem_tile_size, - input_smem_tile_size, + Scalar[_unsigned_integral_type_of[_get_index_type(AddressSpace.SHARED)]()](input_smem_tile_size), ) ``` Instead of doing the above, it's much easier to simply add the new `LayoutTensorIter(.., bound: Int)` constructor, and let the cast to `Self.linear_uint_type` happen inside of the constructor.
