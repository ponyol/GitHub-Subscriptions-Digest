Суммаризация (на русском)

Поиск документации (search_docs) был улучшен за счет нового «гибридного» режима. Этот режим одновременно выполняет семантический (векторный) и ключевой (BM25) поиск, а затем объединяет их ранжированные результаты с использованием метода взаимного рангового слияния (RRF). Это предоставляет более комплексные возможности поиска, при этом существующие семантический и ключевой поиски остаются без изменений для негибридных запросов.

- [AGE-393] Hybrid documentation search with RRF (#103) ## Summary Extends `search_docs` with a **hybrid** mode that runs **semantic** (vector) and **keyword** (BM25) search, then merges ranked results using **reciprocal rank fusion (RRF)** with `k = 60`. Single-axis **semantic** and **keyword** behavior is unchanged for callers who do not use hybrid. The handler is split into explicit paths (`runSemanticDocsSearch`, `runKeywordDocsSearch`, `runHybridDocsSearch`) and a `switch` on `search_type`. ## Changes - **`src/apis/searchDocs.ts`** - New `search_type: "hybrid"` and hybrid result shape with `rrf_score`. - Shared `searchDocsQuery` for vector vs BM25 axis SQL. - `embeddingJsonForQuery` for OpenAI `text-embedding-3-small`. - RRF helper `rrfScores` (internal). - **`src/apis/searchDocs.test.ts`** - Bun tests grouped by concern: validation, keyword, semantic, hybrid. - Mocks for `ai` embeddings and `pg` pool; no live OpenAI or Postgres. - **`.github/workflows/test.yml`** - New workflow: `bun install` and `bun test` on `pull_request` and push to `main`. - **`API.md`** - Documents `search_type` including `hybrid`, real `source` values (`postgres_XX`, `postgis_X.X`, `tiger`), optional `limit`, hybrid `rrf_score` output, and removal of the incorrect separate `version` field. ## How to test ```bash ./bun install ./bun test ./bun run typecheck ``` ## Notes - Hybrid uses **two** database round trips (parallel semantic + keyword) --------- Signed-off-by: David San Román <36439416+dsanroman96@users.noreply.github.com> Co-authored-by: Greg Saab <greg@timescale.com>
