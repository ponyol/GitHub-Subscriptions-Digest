Суммаризация (на русском)

Это обновление добавляет полноценную поддержку упаковки и управления пакетами MCP (.mcpb) в ModelKits, значительно расширяя возможности типов контента. Оно также повышает устойчивость команд `kit list` и `kit remove` за счет обработки отсутствующего локального содержимого и улучшает обработку путей конфигурации, включая учет переменной `KITOPS_HOME`. Кроме того, релиз включает несколько мелких исправлений, обновления документации и различные обновления зависимостей.

Signed-off-by: Angel Misevski <amisevsk@gmail.com> - feat: support packaging MCP Bundles (.mcpb) in ModelKits Adds first-class support for MCP Bundles as a new ModelKit content type: - Introduce the mcpb media type (application/vnd.kitops.modelkit.mcpb.v1+zip) and MCPBBaseType for verbatim-ZIP MCP Bundle layers per the ModelKit MCPB packaging spec. - Add the mcpServers section to the Kitfile with the MCPServer entry type (name, path, description) and validation: required unique names, local-only paths, .mcpb extension, and cross-section duplicate-path checks. - Pack each .mcpb bundle as its own verbatim raw ZIP layer after validating it is a well-formed ZIP with a root manifest.json; the layer digest is the SHA-256 of the file. mcpServers are rejected when packing in modelpack format since the media type is KitOps-local. - Unpack mcpb layers verbatim to their Kitfile path, resolving the target from the config entry's path and writing the blob byte-identical with the same overwrite/ignore-existing semantics as tar extraction. - Support --filter=mcpservers[:name|path] in unpack and include mcpServer paths in LayerPathsFromKitfile so bundles are excluded from sibling layers via the ignore machinery. - Detect local .mcpb files (and directories of bundles) during kit init, adding them as individual mcpServers entries. - Add integration tests for digest-equals-file-sha256, verbatim round-trip byte identity, mcpservers filter selection, and pack failures for malformed bundles and the modelpack format. - Document the mcpServers Kitfile section. Signed-off-by: Gorkem Ercan <gorkem@jozu.com> - fix: use display repository name in list skip warning The skip warning printed the internal <registry>/<repo> form via repo.GetRepoName() while the listing table formats names with artifact.FormatRepositoryForDisplay(), so the warning could show an unexpected localhost/ prefix that doesn't match the listed entries. Compute the display name once per repo and reuse it for both the warning and the table row. Signed-off-by: Gorkem Ercan <gorkem@jozu.com> - fix: tolerate missing content in local list and remove A ModelKit whose blobs are partially missing from local storage (for example, left over from an interrupted removal) caused both `kit list` and `kit remove` to fail, and `remove` left the per-repo index still referencing a manifest that could no longer be read. - list: skip a manifest whose content is missing, logging a warning that points at `kit remove` for cleanup, instead of aborting the entire listing. - remove: treat already-missing content (errdef.ErrNotFound) from the underlying store delete as already-deleted, so the manifest is still removed from the local index and the repository is left consistent.
