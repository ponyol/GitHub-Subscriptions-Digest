Суммаризация (на русском)

This release focuses on improving system stability, user experience, and security. It introduces auto-recovery from corrupt Dolt manifests, prevents accumulation of temporary files after failed fetches, and ensures atomic writes for audit logs. Key new features include a default-on auto-export mechanism, a `started_at` timestamp for issues, and a global database for tracking issues across projects in shared-server mode. The update also includes hardened remote URL validation and numerous dependency and build process updates. --- Этот выпуск направлен на улучшение стабильности системы, пользовательского опыта и безопасности. Он вводит автоматическое восстановление из поврежденных манифестов Dolt, предотвращает накопление временных файлов после неудачных операций загрузки и обеспечивает атомарные записи для журналов аудита. Среди ключевых новых функций — механизм автоэкспорта, включенный по умолчанию, временная метка `started_at` для задач и глобальная база данных для отслеживания задач в разных проектах в режиме общего сервера. Обновление также включает усиленную проверку удаленных URL-адресов и многочисленные обновления зависимостей и процессов сборки.

These accumulate unboundedly across repeated failures and are never cleaned up automatically. Observed impact: 194 GB of tmp_pack_* debris on a single machine after months of failed federation syncs. DoltGC requires a non-transactional connection; if db is a transaction the GC will fail silently, which is acceptable — the original fetch error is still returned correctly.
