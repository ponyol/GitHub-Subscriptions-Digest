Суммаризация (на русском)

Обновление `gptel` добавляет интеграцию с моделью Claude Opus 4.6 для различных бэкендов. Также появилась экспериментальная поддержка `gptel-send` в буферах Vterm, позволяющая генерировать команды на месте, хотя и с некоторыми ограничениями. Важным изменением стала улучшенная обработка пресетов для чат-буферов: теперь пресеты сохраняются по ссылке вместо избыточных индивидуальных настроек, что предотвращает переполнение метаданных и обеспечивает согласованную загрузку конфигурации.

(gptel--vterm-pre-insert): Handle insertion by collecting the response in a temporary buffer and inserting into Vterm at the end. * gptel-transient.el (gptel--suffix-send): Handle "in-place" gptel requests in Vterm buffers. * gptel.el (gptel--handle-pre-insert): Route response insertions to the Vterm handler. - gptel: Record and restore presets when saving buffers Change how metadata is stored to files when writing gptel chat buffers to disk. Now it works as follows: 1. If a preset has been applied (globally or in this buffer), save a reference to the preset. This is similar to how we store the backend name. 2. For all gptel variable values to be stored (model, backend, system message, tools, temperature, max tokens etc), check if their current values are as prescribed by the preset. 3. If they are, don't save them. If they are not, save them as before. When turning on gptel-mode in a chat file, gptel now first applies the preset, throwing a warning if this preset is not available. Then it applies any remaining stored property values. The purpose of this change is twofold: 1. Now you can associate a chat buffer with any collection of gptel settings via applying a preset, and not just the subset that is supported explicitly. 2. Long system prompts often cause the local properties block of Markdown chat buffers to exceed 3000 chars, making the chats un-resumable. See https://github.com/karthink/gptel-agent/issues/60 for an example. Moving the system prompt into a preset avoids this problem. Of course, this has the downside of not making the chat file self-contained any more, but this is already the case since we store only the backend name. * gptel.el (gptel--restore-state, gptel--save-state): Save/restore presets and metadata according to the above scheme. * gptel-org.el (gptel-org--restore-state) (gptel-org-set-properties): Save/restore presets and metadata according to the above scheme.
