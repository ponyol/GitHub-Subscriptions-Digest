This change makes the provider refresh tokens itself, mirroring the canonical @openai/codex CLI (codex-rs/login/src/auth/manager.rs): - Loads tokens.refresh_token from auth.json (previously discarded). - Proactive refresh: decodes the access_token JWT's exp claim and refreshes ~60s before expiry. Cheap when the token is fresh. - Reactive refresh: on a 401/403 from the codex backend, refreshes once and retries the request without consuming a normal-retry budget slot. - Single-flight: serializes through asyncio.Lock so concurrent callers produce one network refresh, not N. Re-checks under the lock by comparing the cached token before/after wait to handle the case where another coroutine rotated mid-wait. - Atomic persistence: writes auth.json via tempfile + os.replace with mode 0600. The upstream Rust CLI uses truncate-and-overwrite, which a concurrent reader can catch mid-write; tempfile+rename is strictly safer. - Terminal error handling: refresh_token_expired/reused/invalidated (and any 401 from the refresh endpoint) raise CodexRefreshExpiredError with a clear "run codex auth login" remediation, and do not loop. - No secrets in logs: refresh logs the reason and outcome but not the token values themselves.
