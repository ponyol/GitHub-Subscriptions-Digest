Это обновление значительно улучшает управление движком LLM и моделями, в частности, за счет сохранения арендных прав на движок до полного завершения HTTP-ответов, что предотвращает преждевременную выгрузку моделей и повышает стабильность при нагрузке на ресурсы, обработке кеша и допуске запросов. This prevents the pool from treating a model as idle while server code still holds the engine, tokenizer, scheduler, or KV state. Behavior matrix: | Scenario | Before | After | | --- | --- | --- | | Idle model, model switch exceeds ceiling | Evict idle LRU and load target | Same | | Multiple idle models under soft pressure | Evict idle LRU when useful | Same | | Final idle non-pinned model under hard pressure | Could be kept loaded | Unload immediately | | Active or leased model under hard pressure | Could remain loaded, or be exposed to unsafe teardown races | Abort requests, mark pending unload, unload after activity drains | | Leased model before scheduler request exists | Could look idle to eviction paths | Mark abort requested, reject before scheduling, unload on release | | Streaming response | Endpoint function returned before body finished, weakening pool protection | Lease stays held until generator finally runs | | Non-streaming JSON response | Engine could be considered idle before body delivery finished | Lease stays held until response body generator finishes | | Runtime-settings reload while busy | Could unload and reload an in-use model | Reject with ModelBusyError / HTTP 409 | | VLM-to-LM force reload while busy | Could unload and reload an in-use model | Reject with ModelBusyError / HTTP 409 | | Competing model load while current model is in-flight | Could unload the current model during the request | Refuse the competing load with 507/409 when needed | | Prefill memory guard thresholds | Unchanged | Unchanged | The intent is not to wait for busy work to finish normally.
