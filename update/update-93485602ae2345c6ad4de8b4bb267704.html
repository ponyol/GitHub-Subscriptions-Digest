Кроме того, улучшенная логика планирования для агента повышает точность бенчмарков, а данные о них теперь датированы.

perf(cuga_lite): default to planning on any task with dependent steps (#331) The prior prompt told the model to "always start with todos" for "complex" tasks (more than one substantial step, multiple API calls, staged data work, several outcomes), and to skip todos for "trivial single-step" work. Analysis of post-leak-fix AppWorld failures (PR #315 baseline) showed the model was over-using the trivial escape hatch: - 5 of 7 failures on the easy bundle had zero create_update_todos calls — the model judged a lookup-then-act chain as "trivial" and skipped planning, then wandered through 7-11 turns without converging - Failed tasks averaged 2.3% todo-turn share vs 6.2% on passes — the inverse of what plan-rigidity would predict, ruling that out - Pattern: the prompt's notion of "trivial" was too broad for AppWorld's typical task shape This change lowers the threshold so the model treats anything with a dependent next step (look up X then act on it; fetch a list then filter or aggregate) as worth planning, and tightens the skip-hatch to immediate one-call answers whose direct response is the final answer to the user. - mcp_prompt.jinja2:29 — replace the "Complex tasks" rule with a "Default to planning" rule keyed on "one round-trip plus reasoning" - mcp_prompt.jinja2:170 — align the section header from "COMPLEX TASKS / MULTI-STEP TASKS" to "DEPENDENT STEPS / DEPENDENT-STEP TASKS" so wording is consistent Both edits gated by {% if enable_todos %}; default behavior unchanged.
