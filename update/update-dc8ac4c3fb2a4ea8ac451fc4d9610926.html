Суммаризация (на русском)

Новая функция позволяет устанавливать настройки доверия для новых чатов на основе значений по умолчанию с сервера. Несколько исправлений улучшают функциональность чата, включая корректное автозаполнение для специальных символов, таких как `@` и `#`, надлежащую обработку опций `askQuestion` без меток, а также обеспечение доступности кнопки "стоп" во время ожидания ответа на вопрос. Кроме того, индикаторы прогресса и спиннеры теперь надежно очищаются по завершении, даже при дублирующихся событиях.

Исходный текст

- feat(chat): use server chat.defaultTrust for new chats Seed new chat trust from the server selectTrust default, falling back to eca-chat-trust-enable so existing behavior is preserved. - fix(chat): complete @/# even when preceded by a non-word char Trigger detection anchored the prefix to the start of the last token, so typing e.g. (# produced no completion. Match the prefix at token start or after a non-alphanumeric char, keeping emails like foo@bar from triggering. - fix(chat): handle askQuestion options without a label The server can send options as plain strings or objects without a label, which made propertize crash with wrong-type-argument stringp nil. Normalize each option to a label and description pair with a non-nil string label before rendering. - fix(chat): keep stop button available while a question is pending A pending question blocks the turn waiting on our answer, but the chat can report idle so the stop affordance disappeared. Treat a pending question like the loading state in the loading/stop segment and in eca-chat--stop-prompt, and refresh the transient area when a question is shown, answered or cancelled. - fix(chat): keep clearing progress and spinner on finished when not loading The wildcard pcase arm that ignores duplicate finished events also dropped the visible cleanup. Still clear progress text, spinner and elapsed timers idempotently, only skipping the trailing newline and queued-prompt dispatch so duplicate events stay harmless.
